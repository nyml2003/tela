# 002 · 统一壳三轴与 13 处漂移收敛

> 状态：✅ 已实施（2026-08-27）。本文记录 Win32 双壳合并为一套参数化壳的裁决依据，
> 供后续 macOS 策略层收敛（`win32.rs ↔ macos/view.rs` ~500 行重复）复用同一套方法。

## 1. 背景

合并前 `crates/targets/win32` 内有两套完整窗口循环：

| 文件 | 行数 | 角色 |
|---|---|---|
| `native.rs`（已删） | 1401 | 静态壳：进程内 `Box<dyn ApplicationSession>`，自绘标题栏（编辑器/变速齿轮） |
| `win32.rs`（已并为 `shell.rs`） | 1473 | SDK 壳：下载 `.tela` → Wasmtime guest，系统外框 |

审计结论：78%/89% 是同一段代码写两遍（~500 行逐字重复 + `gpu.rs` 190 行被内联复制），
且已产生 13 处行为漂移——多数是"修复只打在一侧"的现役缺陷（最典型：光标冻结修复
`8b218ce` 只进了静态壳）。真实差量只有三个轴，不构成两套循环的理由。

## 2. 统一后的结构

```
crates/targets/win32/src/
├── input.rs     纯输入归一化（VK 表/滚轮/字符码单元/消息量子）；不依赖 windows crate，
│                Linux 宿主可单测 —— 两壳漂移的机械重复源头
├── driver.rs    SessionDriver：Box<dyn ApplicationSession> 之上的发布/呈现/令牌/效应
│                簿记（急切发布）；mock 会话可测
├── chrome.rs    WindowChrome{SystemOverlapped, CustomTitleBar}：样式位 + WM_NCHITTEST
│                拖拽带策略 + 窗口命令执行
├── startup.rs   Background 轴：bundle 下载/缓存/校验 + Wasmtime 编译 worker
├── shell.rs     唯一 wndproc/消息循环/WindowState；run_window / run_native_window /
│                run_sdk_window
├── gpu.rs       共享 GpuSession（吸收 device-loss 回调 + 代际守卫 + WM_TELA_DEVICE_LOST）
└── providers.rs 桥 providers + WindowMetrics（原本就共享）
```

三轴：

```rust
pub enum SessionSource {
    Immediate(Box<dyn ApplicationSession>),   // 编辑器/变速齿轮：建窗前同步 initialize + 首帧
    Background(PlatformLaunchOptions),        // SDK：Loading 页先行，worker 就绪后交接
}
pub enum WindowChrome { SystemOverlapped, CustomTitleBar }
```

会话来源经 `tela_guest_runtime::GuestSession` 适配统一：`GuestRuntime` 的
`dispatch/publish_latest/presented/rejected` 映射到 `ApplicationSession` trait（首帧
经 `pending_publication()` 缓存零 WASM 重入），桥泵在适配器内完成——macOS 可直接复用。
动画驱动（`TIMER_ANIMATION` + DwmFlush）与唤醒节拍（`TIMER_WAKE` 500ms）对两轴统一。

## 3. 13 处漂移裁决表

| # | 漂移 | 采纳侧 | 理由 |
|---|---|---|---|
| 1 | WM_SETCURSOR 处理 | 静态壳 | HTCLIENT 检查 + DefWindowProcW 分支：无条件 `LRESULT(1)` 会吞掉 SDK 壳的系统缩放光标 |
| 2 | 光标映射 | SDK 壳 | `Text => IDC_IBEAM`：文本编辑器必须有 I-beam |
| 3 | WM_CHAR Enter | 静态壳 | `13 => '\n'`：多行编辑器换行；单行输入的提交走键盘意图，不受影响 |
| 4 | 初始 DPI | SDK 壳 | 建窗即 `GetDpiForWindow`：否则 150% 显示器上首帧按 dpr=1.0 渲染 |
| 5 | WM_DPICHANGED | SDK 壳 | 应用系统建议矩形：只改内容缩放不改窗口物理尺寸会错位 |
| 6 | SIZE_MINIMIZED/零客户区 | SDK 壳 | 最小化进入 Suspended，停止渲染 |
| 7 | 未处理键/字符 | SDK 壳 | `Ok(false) => DefWindowProcW`：静态壳吞键会挡系统快捷键 |
| 8 | WM_KILLFOCUS | SDK 壳 | 取消捕获 + `PointerPhase::Cancel` + pointer-left：拖拽中失焦不能悬空捕获 |
| 9 | 渲染退避 | SDK 壳 | `ShellLifecycle::surface_timeout` 阶梯（16→250ms）替代 5 次熔断 |
| 10 | device-lost | SDK 壳 | 回调 + 代际守卫 + `WM_TELA_DEVICE_LOST` 一次性恢复（入 `gpu.rs`） |
| 11 | 文本通道 reconcile | SDK 壳 | `synchronize_text_channel` 两遍收敛（Blur 后 guest 可能推进到另一个输入框） |
| 12 | 动画驱动 | 静态壳 | `next_deadline_ms` 定时器（1..16ms 钳制）+ DwmFlush；SDK 壳此前完全没有 Tick 通路 |
| 13 | GWLP_USERDATA | SDK 壳 | `WM_NCCREATE`/`lpCreateParams` 安装 + `Option` 访问器；删除静态壳的伪造回退态 |
| 14 | 消息量子 | 统一 | `as_micros() < 2_000`（语义等价，消除单位漂移） |

## 4. 静态产品（编辑器/变速齿轮）接受的行为增量

I-beam 光标、正确初始 DPI、DPICHANGED 应用建议矩形、最小化挂起、未处理键透传
DefWindowProc、失焦释放捕获、阶梯退避、**输入焦点/blur 改由 lifecycle reconcile 驱动**
（与 demo guest 同一路径；IME 流程是最高风险项，需真机手测）、device-lost 一次性恢复、
会话错误显示 Failed 诊断页（替代日志后继续）。

SDK 壳增量：动画/唤醒定时器（guest 动画首次能推进）、光标修复、guest 内 Enter 换行、
WindowCommand 执行。
