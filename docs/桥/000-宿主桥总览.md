# 000-宿主桥总览

> **状态：📐 设计已确认，MVP 定稿；crate 与传输通道实施见 [032-宿主桥MVP实施目标](../032-宿主桥MVP实施目标.md)。** 本文定义宿主桥体系的统一规则：分组模型、原子性与组合、异步模型、版本模型、传输通道、crate 归属、预留与未来扩展。各桥的具体语义见 [通用模型](通用模型/README.md) 与各组文档（[base](base/001-canIUse.md)、[device](device/001-getAppName.md)、[position](position/001-getCoordinates.md)、[config](config/001-getConfig.md)）。

## 1. 结论

宿主桥是 guest 向宿主请求能力的统一通道。MVP 覆盖 16 个只读原子桥（仅查询类能力，动作类后置），按分组命名空间组织。桥遵守与 app ABI 相同的边界约定：guest 与 host 只交换版本化字节包，不交换 Rust 引用、trait object 或平台句柄。

- **统一外部契约**：所有能力（`std` 公开规范、端侧桥、业务桥）对 guest 一律是外部能力，经同一套发现/版本/请求通道访问；guest 统一视为外部实现者（按 ABI 规范接入，无特权路径）。
- **统一字节通道**：信封携带 `CapabilityId` + 载荷字节（`std` 桥载荷格式由契约文档定义）。
- **每个桥都是原子的**：单一职责、独立可查（canIUse 单独查询）、无隐藏依赖；复杂用法通过组合实现（见 §5）。
- **协议统一异步**：响应 `Response{request_id, result}` 可在任意帧到达，guest 以 `request_id` 关联；host 对本地能力应尽量立即回投（近似同步），异步能力（如定位权限流）跨帧回投。
- **注册必实现，否则不注册**：能力枚举只含已实现能力；预留能力只占命名空间，不注册（canIUse 回 `UnknownCapability`）。
- **版本显式化**：每请求携带 `VersionPolicy`（`Latest` / `Exact` / `Range`），响应回显 `hit_version`。
- **发现机制即 canIUse**：能力存在性、命中版本全部经 `std.base.canIUse` 查询，不做隐式猜测。

## 2. 分组模型

### 2.1 能力 ID

```text
CapabilityScope = Std | Named(String)
CapabilityId { scope: CapabilityScope, group: String, name: String }
// Display："std.device.getBatteryLevel" / "shop.cart.getCount"
```

`std` scope = tela 发布的跨端公开规范；`Named` scope 由实现者注册（端侧如 `web`、`android`，业务如宿主自定义 `shop`）。三类能力经同一注册表执行，无机制差异。

### 2.2 命名规则

| 类型 | 规则 | 示例 |
|---|---|---|
| 只读查询桥 | `get + 名词短语`，一眼看出"拿什么信息" | `getTimeStamp`、`getViewportSize`、`getBatteryLevel`、`getCoordinates`、`getConfig` |
| 动作桥 | 动词（MVP 后置，命名规则先定） | `subscribe`、`unsubscribe`、`publish` |
| 元能力 | 保持固定名 | `canIUse` |

禁止裸动词（`get`/`read`/`now`）单独作名——脱离命名空间必须可读。**MVP 只注册只读桥**；动作桥语义出现时按此规则注册。

### 2.3 MVP 能力集

| 组 | 命名空间 | 原子桥 | 文档 |
|---|---|---|---|
| 基础 | `std.base` | `canIUse`（含 `ListCapabilities` 子请求） | [base](base/001-canIUse.md) |
| 设备 | `std.device` | `getAppName`、`getAppVersion`、`getAppBuildId`、`getBundleVersion`、`getBundleBuildId`、`getTimeStamp`、`getViewportSize`、`getViewportDpr`、`getBatteryLevel`、`getBatteryCharging`、`getNetworkOnline`、`getNetworkKind` | [device](device/001-getAppName.md) |
| 位置 | `std.position` | `getCoordinates` | [position](position/001-getCoordinates.md) |
| 配置 | `std.config` | `getConfig` | [config](config/001-getConfig.md) |

### 2.4 预留（命名空间已定，能力不注册）

| 命名空间 | 计划能力 | 说明 |
|---|---|---|
| `std.route` | `open` / `canOpen` / `onChange` | tela 自定义路由协议，URI 规范草案见 [reserved](reserved.md) |
| `std.storage` | `getValue` / `setValue` / `removeValue` / `listKeys` | 持久化存储，MVP 不做 |
| `std.user` | `profile` 等 | 依赖宿主身份系统，MVP 不做 |
| `std.device` 扩展 | `clipboard` | 权限差异大（webview 需 HTTPS/用户手势），后置 |
| `std.position` 扩展 | `watch`（连续定位） | 依赖消息推送成熟后接入 |
| `std.pubsub` | `subscribe` / `unsubscribe` / `publish` | 消息总线（topic 纯字符串、精确匹配、纯实时），MVP 只做只读桥故后置 |

预留只保留命名空间与能力名，**不进 canIUse 静态表**；canIUse 对预留能力回 `UnknownCapability`，不违反"注册即实现"。

## 3. 原子性与组合

- **原子桥定义**：单一职责（一个动作/一次查询）、独立可查、无隐藏依赖、不依赖其他桥的内部状态。禁止"大而全"能力（如 `std.device.getAll`）。
- **拆分判据（前瞻性原则）**：能力聚焦"到底拿什么信息"，**字段独立消费 → 独立原子桥**；**绑定消费（语义成对，如经纬度、逻辑宽高）→ 合并**。每个原子桥只回答一个问题：
  - `getViewportSize` 只回答"内容区多大"；`getViewportDpr` 只回答"像素比多少"——页面按场景组合（布局要 size、资源选择只要 dpr）。
  - `getBatteryLevel` 只回答"还有多少电"；`getBatteryCharging` 只回答"是否在充电"。
  - `getNetworkOnline` 只回答"有没有连接"；`getNetworkKind` 只回答"什么类型连接"。
  - 反例：`battery` 同时回 level+charging、`network` 同时回 online+kind——native 实现方便，但页面只能全量拉取，不够灵活。
- **组合在 guest 层**：一个页面可同时发起多个原子请求（各自 `request_id`，响应独立关联、任意顺序到达）；宿主不提供组合能力。
- **正交性**：MVP 各桥完全正交，无显式依赖；依赖规则（如消息归属）随 pubsub 预留回归时定义（见 [reserved](reserved.md)）。

## 4. 异步模型

- **协议层（契约，统一异步）**：`BridgeEvent::Response { request_id, result }` 不承诺在同一 dispatch 闭环内到达；host 在任意帧回投，guest 以 `request_id` 关联，不做时序假设。
- **host 层（实现自由度）**：
  - 本地能力（`canIUse` / `getAppName` / `getAppVersion` / `getAppBuildId` / `getBundleVersion` / `getBundleBuildId` / `getTimeStamp` / `viewportSize` / `viewportDpr` / `batteryLevel`* / `batteryCharging`* / `networkOnline` / `networkKind` / `getConfig`*）：读取自身状态，**应同一轮请求队列处理内回投**（guest 感知近似同步）。
  - 异步能力（`position.getCoordinates` 权限流、webview 的 batteryLevel/batteryCharging 平台 Promise）：完成时投递回持有 guest 的线程再回投，允许跨帧。
  - `*`：battery 两桥在多数端是同步读，仅 webview 为 Promise；`getConfig` MVP 为静态表（同轮），未来远程数据源可能跨帧——语义相同，时序由 host 保证。
- **guest 层**：统一 callback + pending 表（`request_id` → 回调），不区分同帧/跨帧；响应到达时在 `tela_app_bridge_dispatch` 入口分发。
- **超时**：`BridgeError::Timeout` 为防御性保留；MVP host 可不实现超时。

## 5. 组合小 demo

以下示例展示 guest 侧组合原子桥（Rust，`tela-bridge` guest facade）：

```rust
// 设备状态卡片：getBatteryLevel + getNetworkOnline + getConfig 并发组合（按需聚焦，三个请求独立关联）
bridge.get_battery_level(|battery| {
    match battery {
        Ok(b) => set_battery_ui(b.level),                // 电量 UI：只要电量水平
        Err(_) => set_battery_ui_unknown(),              // 能力失败不拖垮整页
    }
});
bridge.get_network_online(|network| {
    if let Ok(n) = network { set_offline_banner(!n.online); }  // 离线提示：只要在线状态
});
bridge.get_config("app.theme", |config| {
    match config {
        Ok(ConfigValue { value: theme }) => apply_theme(theme),
        Err(BridgeError::KeyNotFound) => apply_default_theme(),   // SDK 兜底：直接回 Err
        Err(_) => {}                                              // 其他失败不拖垮整页
    }
});

// 定位页：拉取单次位置（WGS84 坐标）
bridge.get_coordinates(|position| {
    match position {
        Ok(pos) => show_coordinates(pos),
        Err(BridgeError::PermissionDenied) => prompt_authorize(),
        Err(_) => show_location_error(),
    }
});

// 关于页：版本信息组合（四个请求独立关联）
bridge.get_app_name(|name| { if let Ok(n) = name { set_title(n.name); } });
bridge.get_app_version(|v| { if let Ok(v) = v { show_version(v.version); } });
bridge.get_bundle_version(|v| { if let Ok(v) = v { show_bundle_version(v.version); } });
bridge.get_bundle_build_id(|v| { if let Ok(v) = v { show_build_id(v.build_id); } });
```

要点：每个原子调用互不阻塞、独立回调；失败局部化；页面按需并发组合。

## 6. 版本模型

版本号与版本策略是**通用模型**：`Version`（通用三元组，桥能力/应用/交付构建三类场景复用）与 `VersionPolicy`（`Latest` / `Exact` / `Range`）的完整定义与匹配规则见 [通用模型](通用模型/README.md) §2-§3，本文不重复。

- 桥能力 bump 规则由各桥文档逐版本记录语义。
- 策略不满足 → `BridgeError::VersionMismatch { policy, available }`，host 回显实际版本，不做模糊降级。
- **canIUse 自身版本化**：host 实现的 canIUse 版本不满足 guest 策略 → 拒绝，保证发现机制本身语义稳定。

## 7. 传输通道

### 7.1 导出规范（零宏，guest 手写实现）

桥 ABI 与 app ABI（`export_guest!`）**完全独立**：桥的 4 个导出由 guest 按规范自行实现（`tela-bridge` 提供 `GuestBridge` 参考实现与手写样板，不生成代码）。任何语言的 WASM 均可按此规范接入；不实现则 host 探测不到 → 桥透明不可用。

| export | 方向 | 作用 |
|---|---|---|
| `tela_app_request_begin(len) -> ptr` | guest→host | 保留请求队列线性内存，guest 排队请求 |
| `tela_app_request_len() -> u32` | host 读 | 每次 dispatch 后读取排队请求长度 |
| `tela_app_bridge_dispatch_begin(len) -> ptr` | host 写 | 保留响应内存（host 写入 BridgeEvent 字节） |
| `tela_app_bridge_dispatch(len)` | host 调 | guest 解析响应 → 按 request_id 触发回调 → guest 自行发布新帧 |

### 7.2 host → guest（响应/事件）

`BridgeEvent` 包自带 magic 与 packet version，与 app ABI 版本解耦。

一次闭环（同步能力）与异步完成（跨帧）：

```text
host dispatch 输入
  -> guest 处理并排队 BridgeRequest，发布帧
  -> host 读请求队列，解码，版本校验
  -> host 执行 provider
     - 本地能力：立即编码 BridgeResult
     - 异步能力：挂起，平台回调完成后投递回 UI 线程再编码
  -> host 调 tela_app_bridge_dispatch 回投 BridgeEvent（可在任意帧）
  -> guest 解析 pending 请求（按 request_id 关联），发布新帧
```

### 7.3 iOS 静态路径

iOS 静态链接移动应用，不走 wire：guest facade 直接调用注入的 `Provider` 实例，异步语义一致（回调 → 完成 → 触发 guest 回调）。

## 8. crate 归属

`crates/delivery/bridge/`（package `tela-bridge`），纯契约层，零平台依赖，风格对齐 `tela-app-abi`（postcard + magic `TLBR` + 自持 packet version，`forbid(unsafe)` + `warn(missing_docs)`）：

- 通用模型：`Version` / `VersionPolicy` / `CapabilityId`（scope+group+name）/ `BridgeError` / 协议信封（`Topic` 随消息总线预留），完整定义见 [通用模型](通用模型/README.md)，本文不重复。
- `BridgeEvent`：MVP 仅 `Response { request_id, result }`；`Message { topic, payload }` 为 pubsub 预留（[reserved](reserved.md)）。
- 载荷格式：`payload` 模块提供各 `std` 桥的编解码辅助（`encode_get_config_request` / `decode_battery_level_response` 等），协议不承载类型化枚举。
- codec：`encode_request / decode_request / decode_request_stream / encode_event / decode_event`

feature 划分：

| feature | 内容 |
|---|---|
| `guest` | `GuestBridge` 参考实现：请求队列 + request_id 分配 + 关联回调 facade（`can_i_use(..)` / `get_app_name(cb)` / `get_app_version(cb)` / `get_app_build_id(cb)` / `get_bundle_version(cb)` / `get_bundle_build_id(cb)` / `get_time_stamp(cb)` / `get_viewport_size(cb)` / `get_viewport_dpr(cb)` / `get_battery_level(cb)` / `get_battery_charging(cb)` / `get_network_online(cb)` / `get_network_kind(cb)` / `get_coordinates(cb)` / `get_config(..)` + 通用 `request(capability, version, payload, cb)` 供端侧/业务能力），统一异步 callback 语义；4 个导出由 guest 手写转发 |
| `host` | 统一 `Provider` trait（`version()` + `handle(payload) -> ProviderOutcome`）+ `BridgeDispatcher` **注册表模型**（`register(capability, provider)`；std / 端侧 / 业务统一注册；版本门 → 分发 → 回投；`complete(request_id, result)` 供异步完成投递） |

**不创建万能 Host trait**；统一窄 `Provider` trait，每能力一个实例，Target/宿主自行注册组合。

### 错误语义

`BridgeError` 全集见 [通用模型](通用模型/README.md) §6（`UnknownCapability` / `VersionMismatch` / `PermissionDenied` / `Timeout`）。

## 9. Target 实现要点

| Target | 首期范围 |
|---|---|
| webview | 全实现 16 只读桥；canIUse 静态表 + 浏览器探测（navigator/screen/timezone）；getViewportSize/getViewportDpr 来自 canvas CSS 尺寸 + `devicePixelRatio`；getBatteryLevel/getBatteryCharging 走浏览器 Promise（异步回投）；getCoordinates 走 `navigator.geolocation` |
| win32 | 全实现 16 只读桥（OS API：本地时间、系统信息、WinRT Battery/NetworkInformation）；getViewportSize 来自 `GetClientRect`、getViewportDpr 经 `GetDpiForWindow`；position 走 UWP `Windows.Devices.Geolocation` |
| macOS | 全实现 16 只读桥（AppKit/Foundation：NSDate/NSTimeZone、IOKit 电量、SCNetworkReachability）；getViewportSize 来自 `NSView.bounds`、getViewportDpr 来自 backing scale；position 走 CoreLocation |
| android | 全实现 16 只读桥（`Build.*`、`Build.VERSION.*`、`BatteryManager`、`ConnectivityManager`）；getViewportSize 来自 surface 尺寸、getViewportDpr 来自 `density`；position 走系统定位 |
| iOS | 全实现 16 只读桥（`UIDevice`/`NSProcessInfo`、`NSTimeZone`、`UIDevice.battery`、网络状态）；版本四桥为构建常量注入（不读 CFBundle，与 App 壳解耦）；getViewportSize 来自 view bounds、getViewportDpr 来自 `scale`；position 走 CoreLocation |

canIUse 的 host 实现 = **构建期静态表**（每 Target 生成），MVP 十六只读能力全部实现；静态表已注册的能力必须成功响应。

## 10. 未来扩展

### 10.1 预留与进入 std 的时机

| 能力 | 语义归属 | 进 std 前提 |
|---|---|---|
| `pubsub.subscribe` / `unsubscribe` / `publish`（消息总线） | `std`（跨端语义一致，topic 纯字符串精确匹配） | 动作桥需求出现（MVP 只做只读桥） |
| `route.*`（URI 路由） | `std`（跨端语义一致，URI 规范见 [reserved](reserved.md)） | 路由协议定稿 + 全端实现就绪 |
| `storage.*`（持久化） | `std`（语义跨端一致，实现细节归 host） | 出现真实消费方 |
| `user.*`（用户信息） | 依赖宿主账号体系，语义跨端差异大 | 出现真实消费方并统一语义 |
| `device.clipboard` | `std`（权限流差异大） | webview HTTPS 约束与权限语义收敛 |
| `position.watch`（连续定位） | `std`（订阅式推送） | pubsub 消息推送成熟后接入 |

**注册即承诺全端实现**：任何能力进入 std 枚举时，五个 Target 必须同时具备实现，否则不注册。

### 10.2 消息总线机制回归

MVP 只做只读桥，消息总线整体后置（[reserved](reserved.md) §3 记录）：`subscribe` / `unsubscribe` / `publish` 三动作桥、纯字符串 topic 精确匹配、`BridgeEvent::Message` 推送。以下机制随总线回归一并设计：结构化 `Namespace`（段数组）、页面命名空间（`page.<page_id>.<root_tag>` + root_tag 签发）、`registerNamespace` 注册与前缀校验、级联订阅、`std` 前缀发布保护、消息缓存/回放与发布策略。回归时按 breaking change 处理。

## 11. 验收

- codec round-trip：request/result/event 编解码与版本头校验。
- `VersionPolicy` 三策略匹配矩阵：`Latest` / `Exact`（相等与不等）/ `Range` 边界（`lower: None` = 0.0.0、`upper: None` = 255.255.255、闭区间端点包含）。
- 桥能力 / 应用 / 交付构建三类场景复用同一 `Version` 类型，无重复定义。
- `UnknownCapability`（预留/未知能力）路径。
- 请求队列：多次请求按 request_id 关联、乱序安全（mock 延迟 provider）。
- 同步能力同轮回投断言；异步能力跨帧回投断言。
- 桌面闭环：guest 请求 → host 执行 → BridgeEvent → guest 解析并发布新帧。
- 各 Target canIUse 静态表与实现一致性：注册即实现。
- `getViewportSize`/`getViewportDpr` 拉取值与最新 `AppEvent::Viewport` 一致（同源快照）；组合换算物理尺寸正确。
- `position.getCoordinates`：缓存命中不触发系统获取；权限拒绝回 `PermissionDenied`；datum 恒 `WGS84`（无转换时）。
- `config.getConfig`：命中返回 JSON、未命中回 `KeyNotFound`、非法 key 拒绝。
