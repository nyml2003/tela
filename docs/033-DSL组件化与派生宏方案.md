# 033-DSL 组件化：自定义组件、派生宏与指令重构方案

> 状态：🟢 已实施（2026-08）。trait/宏/derive/原语组件/迁移全部落地，ops check 三门通过
> （test 门仅剩 GPU 环境测试 `write_texture_readback_works` 失败——本机无 lavapipe，预存在）。
> 承接：031 的 `ui!` DSL 与帧期订阅；030 的 Headless / Signal / 双 Kit 方案。
> 范围：`tela-ui-dsl`、`tela-ui-dsl-macros`、`tela-ui-foundation` 的组件契约与宏解析；不改变 Kernel 分层责任。
> 目标：DSL 只保留一个概念——**组件**。组件可见性由 Rust `use` 决定；宏只做属性搬运工；
> 编译器负责一切名称/类型/约束校验。`@provide/@inject/@watch` 调用点指令消亡，能力内聚到
> 派生宏字段属性。

## 0. 背景与动机

### 0.1 现状：标签白名单 + 调用点指令

当前 `ui!` 宏只有 14 个内建原语标签（dsl-macros `generate_element` 白名单 match）：

```
Column / Row / Frame / View / Stack / ScrollView / Fragment /
ActionTarget / For / VirtualList / Text / Icon / Image
```

- 未知标签直接报 `unsupported DSL tag`——**没有任何自定义组件能力**。
- kit 组件（`tela_ui_foundation::Button`）只能以 `{ expr }` 子表达式嵌入，写不出
  `<Button width={72}/>` 的标签形式。
- `@provide/@inject/@watch` 是调用点指令：位置敏感（`DirectivePhase` 状态机）、显式类型注解
  （`@provide(value: Type)`）、`&signal` 引用强制、只限 ui! 顶层（`BodyScope::Node` 报错）。
- 全仓库数据：`@provide`/`@inject` **零生产使用**；`@watch` 仅 mobile-demo 2 处 + 1 个 example。

### 0.2 调研结论：Dioxus/Leptos 的约定式组件

Dioxus RSX 模式：组件 = 普通 Rust 函数 + `#[derive(Props)]`；rsx 宏把标签编译期解析为
**当前作用域内的路径**；**无注册表**（作用域 = Rust `use`，别名 = `use X as Y`）；类型校验
全部由编译器原生给出。rsx 是 Rust 宏（内嵌），不是独立文件（独立 UI 文件是 Vue/Svelte 路线，
与本项目"Rust 即 UI"冲突，不做）。

## 1. 最终方案（六点定稿）

### 1.1 核心模型统一（彻底抛弃白名单）

- **所有 UI 元素（Row、Column、Text、Button、自定义组件）在 DSL 层面地位完全平等**。
- 删掉宏里的硬编码标签匹配表。`<Row>` 和 `<MyButton>` 走完全相同的解析路径。
- **代价与收益**：原语（Row/Column 等）像普通组件一样实现 `DslComponent` trait（薄薄一层
  DSL 适配，底层 Builder API 保留），用户通过 `use tela_ui_core::prelude::*;` 一次性引入。
  多一个 `use`，换来整个 DSL 语法高度统一。

### 1.2 名称解析（重名、别名）：彻底甩锅给编译器

- **宏的准则**：解析 `<Tag>` 时，宏生成的代码里**原样保留标识符**（`#Tag` 原样放回）。
- **绝不拼接绝对路径**（如 `::my_crate::#tag`），否则别名会失效。
- **用户处理冲突**：`use pkg_a::Button as AButton;` 或写绝对路径 `<pkg_a::Button>`。
  宏不插手中途，全由 Rust 类型系统接管，编译报错即校验。

### 1.3 组件定义：约定优于配置

- 直接给业务 `struct` 加 `#[derive(DslComponent)]`。**结构体字段 = Props**，不再另写
  Props 结构体。
- **默认标签名 = 结构体名**（`struct NavButton` → `<NavButton />`）。
- 仅当需避开 Rust 关键字（如 `Box`）或对外暴露缩写时，才通过 `#[tela(tag = "xxx")]`
  手动覆盖。普通场景绝不多写这个属性。

### 1.4 指令（@provide/@watch）消亡：迁移为字段属性

- 删除 `@provide`、`@inject`、`@watch` 这些调用点"咒语"。
- 能力内聚到派生宏的字段属性中（`#[inject]`、`#[provide]`、`#[watch(key = "...")]`），
  由 derive 自动生成 `build.context().inject()` / `ProvidedValue` 压栈 /
  `watch_source` 订阅脚手架。
- 位置敏感问题消失；能力只能在组件内部使用，符合逻辑边界。

### 1.5 宏的最终职责（极简）

- 收集标签属性 → 填入 `#Tag::Props { ... }` → 调用
  `<#Tag as DslComponent<A>>::render(build, props, children)`。
- **零校验、零作用域判断、零白名单**。不产生任何额外的运行时注册开销。

### 1.6 唯一需要补充的"基础设施"工作

- 给所有原语（Row、Column、Frame 等）手动实现 `DslComponent` 适配层（内部调用现有的
  Builder 构建逻辑）。
- 原语适配层放 **`tela-ui-dsl` 内**（依赖方向：dsl → core，无循环；`DslComponent` trait
  也在 tela-ui-dsl）。`tela-ui-foundation` 的 Button 等加 `tela-ui-dsl` 依赖实现 trait
  （组件库依赖 DSL 框架，方向合理）。
- prelude 导出这些原语，方便 `use tela_ui_core::prelude::*;` 一次性全部引入。

## 2. 落地澄清（C1-C3）

### C1. 控制流语法不属于"UI 元素"，保留宏级（已实施修订）

`For`/`VirtualList`（迭代块 `for x in items {...}`）是**语法**而非组件；`Fragment` 是
透明容器。三者保留在宏里。**ActionTarget 保留宏内建（C1 修订，实施中实证）**：组件契约
的 `type Props` 不能依赖调用点的动作类型 `A`（`Tag::Props` 关联类型因泛型无法在调用点
构造，Rust E0223/E0282 实证死路），而 ActionTarget 的 Props 必须含 `action: Option<A>`——
动作绑定本质是帧期计划注册，与控制流同类，保留宏内建。

### C2. 依赖方向

- `tela-ui-dsl`：`DslComponent` trait + 原语适配层（Row/Column/Frame/View/Stack/ScrollView/
  Text/Icon/Image 的 `DslComponent` 实现，内部复用 `LayoutContainer`/`Primitive`/`NodeKind`
  builder）+ prelude。
- `tela-ui-foundation`：加 `tela-ui-dsl` 依赖，Button 等实现 `DslComponent`（builder API 不动）。

### C3. `key` 属性第一期约定

`key` 是 DSL 通用身份属性（宏在节点生成期经 `with_semantic_key` 处理）；组件返回
`ViewOutput` 后无法再改 key。**第一期：组件标签的 `key` 属性报错**（提示在组件内部节点
设置 key）；二期再设计 ViewOutput 携带 key。

## 3. 组件契约与宏展开

### 3.1 `DslComponent` trait（tela-ui-dsl 新增）

```rust
pub trait DslComponent<A> {
    type Props: Default;              // struct 即 Props；字段名 = 标签属性名
    fn render(
        build: &mut ViewBuild<A>,
        props: Self::Props,
        children: Vec<ViewChild<A>>,  // <Tag>...</Tag> 子节点
    ) -> ViewResult<ViewOutput<A>>;
}
```

- `children` 作为 **render 参数**（非 Props 字段）——Props 免泛型化，组件签名统一；
  无子节点组件传 `Vec::new()`。
- 组件 = **可编程的 view builder**：render 拿到 `build` 与泛型 `A`，内部可用任何 DSL。
- 手写实现与 derive 并存（derive 是糖）。

### 3.2 宏展开（dsl-macros）

`generate_element` 重写为：
1. **控制流语法**（For/VirtualList/Fragment）→ 保留现有生成逻辑。
2. **其余全部** → 组件解析：

```rust
// <NavButton label={"设置"} selected={sel}>"文字"</NavButton>
<#Tag as #dsl::DslComponent<A>>::render(
    build,
    #Tag::Props { label: "设置", selected: sel, ..Default::default() },
    vec![/* 子节点降级结果 */],
)
```

- 属性解析复用现有 `name={expr}` / 字面量语法，值直接作为 Props 字段表达式。
- 未提供的字段走 `..Default::default()`（trait 约束 `Props: Default`）。
- **编译期保证**（全部由 Rust 编译器原生给出，宏零校验）：

| 错误场景 | 编译器报错 |
|---|---|
| 标签名不存在（没 use） | `cannot find type Tag in this scope` |
| 组件没实现 `DslComponent` | `the trait bound Tag: DslComponent<A> is not satisfied` |
| 属性名拼错 | `no field named xxx on type Tag::Props` |
| 标记 default 的字段类型无 Default | derive 生成的类型 assert 报错（见 3.3） |
| `key` 属性（第一期） | 宏报"组件内请用节点 key" |

### 3.3 `#[derive(DslComponent)]`（dsl-macros 同 crate）

```rust
#[derive(DslComponent)]
#[tela(tag = "NavButton")]              // 可选；默认 = 结构体名
struct NavButton {
    label: String,                       // 普通 prop（必填语义见 D3）
    #[prop(default = 72.0)]
    width: f32,                          // 可选 prop：类型必须实现 Default（编译期 assert）
    #[prop(option)]
    title: Option<String>,               // 可选 prop：类型必须形如 Option<U>（编译期 assert）
    #[inject]
    theme: AppTheme,                     // ← 替代 @inject：自动 context.inject::<AppTheme>()
    #[provide]
    scope_value: SomeValue,              // ← 替代 @provide：自动 ProvidedValue 压栈
    #[watch(key = "win32.count")]
    count: i32,                          // ← 替代 @watch：自动订阅，变化重建
}

impl NavButton {
    // 组件作者写渲染逻辑（self 里所有字段已就绪）
    fn view(&self, build: &mut ViewBuild<A>, children: Vec<ViewChild<A>>)
        -> ViewResult<ViewOutput<A>> { ui!(build { ... }) }
}
```

derive 生成：
1. `impl<A> DslComponent<A> for NavButton { type Props = NavButton; ... }`。
2. render 脚手架：`#[inject]` → `build.context().inject::<T>(site())?`；
   `#[provide]` → `ProvidedValue::new::<T>(value)` 压栈；
   `#[watch(key)]` → `Signal` 克隆 + `build.watch_source(&signal, site())?`。
3. **类型 assert（编译期强制）**：
   - `#[prop(default = ...)]` 字段：`const _: () = { fn assert<T: Default>() {} assert::<#field_ty>(); };`
   - `#[prop(option)]` 字段：类型必须 `Option<U>`（类型级检查，不满足则编译错误）。
     `#[prop(option)]` **仅用于编译期类型校验**（确保字段为 `Option<U>`），**不改变字段的
     默认值语义**（`Option` 字段默认即 `None`，与 `..Default::default()` 行为一致）。
4. 组装用户 `view(&self, build, children)` 调用。

## 4. 指令删除与底层 API 保留

dsl-macros 删除：`parse_directive`、`DirectivePhase` 状态机、`Item::Provide|Inject|Watch`、
`BodyScope::Node` 分支、`@batch` 提示。DSL 语法只剩：`<Tag/>`（组件/控制流）、`{ expr }`。

保留的底层 API（derive 生成代码与手写 trait 使用）：
- `ProvidedValue` / `ViewContext`（context.rs）——提供/注入语义不动。
- `ViewBuild::watch_source` / `ComponentRuntime::reconcile`（runtime.rs）——订阅语义不动。

迁移：
- mobile-demo 2 处 `@watch` → `#[watch]` 组件（或手写 trait）。
- `@provide`/`@inject` 零生产使用，直接删除语法。
- example `frame_cost.rs` 1 处 `@watch` 同步迁移。

## 4.5 已知限制（实施实证）

- **For/VirtualList item 内的 `#[watch]` 不锚定业务 key**：组件 watch 锚组件在树中的
  auto-path 位置（旧 `@watch` 锚 item 业务 key，随重排/释放跟踪）。虚拟列表窗口释放时
  watch 仍随组件卸载释放（安全），但 item 重排后 watch 不跟随原 item。二期恢复：
  组件级 `#[watch]` 支持显式业务锚（如 derive 解析 For item 上下文）。
- **Text 的单表达式子节点语法废弃**：`<Text>{"..."}</Text>` 迁移为 `<Text value={...} />`。
- **原语 `width`/`height` 属性收 `f32`**：`width={Size::fixed(72.0)}` 迁移为 `width={72.0}`。

## 6. 决策记录

| # | 决策 | 理由 |
|---|---|---|
| D1 | 核心模型统一：彻底抛弃标签白名单，原语与自定义组件地位平等 | DSL 只有一个概念"组件"，语法统一，宏代码量最低 |
| D2 | 名称解析原样保留标识符，绝不拼接绝对路径 | 别名（`use as`）与作用域由 Rust 模块系统免费提供 |
| D3 | struct 即 Props，默认标签名 = 结构体名，`#[tela(tag)]` 仅规避关键字时使用 | 约定优于配置，少写代码 |
| D4 | `@provide/@inject/@watch` 全部删除，迁移为字段属性 | 零生产使用（provide/inject），@watch 仅 2 处；位置敏感/类型注解/&signal 问题一并消失 |
| D5 | 宏职责极简：收集属性 → Props 字面量 → render 调用，零校验 | 编译期校验全部由 Rust 类型系统/derive 类型 assert 承担 |
| D6 | `children` 作为 render 参数（非 Props 字段） | Props 免泛型化，组件签名统一 |
| D7 | `#[prop(default)]` 字段必须 `T: Default`；`#[prop(option)]` 字段必须 `Option<U>`（编译期 assert） | 严格 trait 约束，错误在编译期暴露 |
| D7b | `#[prop(option)]` 仅用于编译期类型校验（确保字段为 `Option<U>`），**不改变字段的默认值语义**（`Option` 默认 `None`，与 `..Default::default()` 行为一致） | 校验与默认值解耦：标记不隐式修改类型/默认值，语义可预期 |
| D8 | 普通字段缺失 = `..Default::default()` 兜底；`#[watch]`/`#[provide]` 字段缺失 = **返回 `ViewBuildError::MissingRequiredProp`**（整帧 Err，不 panic） | 调用点宏无法内省字段清单；watch/provide 是"必须由调用点提供"的强语义，错误返回优于 panic |
| D9 | 控制流语法（For/VirtualList/Fragment）保留宏级；ActionTarget 组件化 | 控制流是语法非 UI 元素；ActionTarget 的 `action: A` + children 可由 `DslComponent<A>` 表达 |
| D10 | 原语适配层放 `tela-ui-dsl`；foundation 加 dsl 依赖 | 依赖方向：组件库依赖 DSL 框架，不破坏分层 |
| D11 | `key` 是 Props 的约定字段（`Option<String>`，原语组件手写声明；derive 组件用户声明则生效） | 宏统一 `key: Some((expr).into())`，未声明 key 字段的组件编译报 `no field named key` |
| D12 | 不支持独立 rsx 文件 | 宏内嵌即 Tela 的 rsx；独立文件 = Svelte 工具链，与"Rust 即 UI"路线冲突 |
| D13 | derive 与手写 trait 并存 | derive 是糖；builder 组件 API 不动，迁移平滑 |
