# 007-绘制与渲染后端

## 1. 绘制原语清单

基座提供基础通用视觉能力，全部作为 `DrawCommand` 变体表达，与后端无关：

| 原语 | 说明 |
|---|---|
| 矩形 | 实心/描边 |
| 圆角矩形 | 独立四角圆角半径 |
| 圆形 / 椭圆 | |
| 多边形 | 顶点列表 |
| 图片 | 纹理引用（经宿主加载） |
| 文字 | 字形引用 + 文本 + 多字号 + 行间距 |
| 九宫格拉伸 | 3×3 切分的可拉伸贴图 |
| 渐变 | 线性/径向，颜色断点 |
| 阴影 | 外阴影/内阴影 |
| 蒙版裁剪 | 用区域裁剪子内容；以命令级预合并 clip rect 表达（布局层展开，见 2） |

- 文字支持多字号、行间距，单行与多行展示。
- 基座只提供绘图原语，**不内置任何业务组件**（按钮/输入框/表格由上层组件套件实现）。

## 2. 命令与后端解耦

绘制结果（`UiFrame`）只含 `DrawCommand` 序列与命中区域，后端仅实现 `FrameSink` 消费命令，不依赖布局与树逻辑。

```
FrameSink {
  submit(frame: UiFrame)
}
```

- 绘制命令按树顺序产生，顺序即 z 序，后绘制者在上；**同一直接父容器内可被 `VisualConcern.draw_order` 局部重排**（分组 InnerBottom → Normal → InnerTop，组内按权重升序，同组同权重保留树序），命中区域顺序与绘制顺序一致（见 [006-布局引擎](006-布局引擎.md) 4.5）。
- **每条 `DrawCommand` 携带可选 `clip: Option<ClipRect>`（预合并）**：遍历/命令生成阶段把祖先裁剪区域（滚动视口、`clip` 容器）逐层求交，得到该命令的最终裁剪区域。后端绘制时按 clip 直接裁剪，**不维护裁剪栈**；`HitRegion` 携带同一预合并 clip，命中测试做点-in-rect 即可，无需逐层裁剪换算。
- **不提供独立 z-index 数值维度**：层级仅由树序（命令顺序）决定；ModalHost 页面/模态栈保证栈顶子树命令强制在普通界面之上，天然全局最上（见 [006-布局引擎](006-布局引擎.md) 4.1）。
- 绘制层**只消费 `visual` + `content` 维度**（`VisualConcern`/`ContentConcern`，见 [003-场景树与节点模型](003-场景树与节点模型.md)），几何来自布局输出（`LayoutBox`），不读取 `layout`/`interact`/`identity` 的其余语义。
- 后端把命令翻译成自身绘制调用（wgpu 绘制 / canvas API / 软件光栅）。
- 后端不需要知道命令的来源（Full 或 Dirty、何种布局引擎），只需按序绘制。

## 3. 优雅降级

平台不支持的特殊视觉效果**优雅降级，不崩溃**。降级是**各后端消费时的本地行为**，`resolve` 阶段不做任何特效降级：

- **`UiFrame` 是后端无关的完整指令集**：阴影、径向渐变等高阶原语全部保留，同一棵树永远输出同一套 UiFrame——可序列化保存，喂给任意后端复现（快照测试与问题复现的基石）。
- 每个渲染后端读取自身 `BackendCapabilities`，在自己的绘制预处理步骤做降级：raster 替换/丢弃高耗特效，wgpu 完整执行。

| 特效 | 不支持时的降级 |
|---|---|
| 渐变 | 退化为平均色 / 首断点纯色 |
| 阴影 | 丢弃阴影，仅绘制本体 |
| 九宫格 | 退化为整体拉伸 |
| 蒙版裁剪 | 退化为矩形裁剪 / 丢弃裁剪 |
| 多边形（非凸/复杂） | 退化为外接矩形或分片三角形（按后端能力） |
| 圆角 | 退化为直角 |

- 降级策略是**声明式**的：`BackendCapabilities` 由各后端自报，降级逻辑位于后端本地预处理，**不改动 UiFrame**。
- 同一套界面描述在弱环境与强环境下布局一致，仅视觉细节不同。

## 4. 文字与字形

- 文字绘制需要字形度量（宽度、行高）参与布局（Auto 尺寸），因此度量必须可离线执行。
- 字形资源由 renderer/宿主侧加载；核心不加载字体文件。
- core 继续只接收 `TextMeasurer`；默认受控实现由 `tela-text` 提供，保证 demo、Raster 与 WGPU 的度量和绘制定位不分叉。

### 4.0 字体管线（决策：ab_glyph）

- 字形解析与度量：`ab_glyph`（TTF/OTF 解析、字形度量、缩放）。
- **缩放按 em（`units_per_em`）而非行高**：`as_scaled(font_size)` 按 ascent-descent 缩放，
  与 CJK 字体的轮廓单位不一致（如 Noto CJK：vertical metrics 1448 vs upem 1000）会把字形缩到
  0.69em；统一用 `em_pixel_height(font, size) = size × height_unscaled / upem` 保证 1em = font_size
  （CSS 语义），度量与渲染共用同一缩放（`tela-text` 内部实现）。
- 受控管线：`tela-fonts` 提供正文 `tela-ui` 与图标 `tela-icons` 的内嵌字节 → `tela-text` 按
  `FontRef` 稳定选择或回退正文 → `ab_glyph` 生成 `TextMetrics` 与字形覆盖事件 → demo 注入
  `ControlledTextMeasurer` 给 core，Raster/WGPU 各自消费同一覆盖事件混合到位图或纹理。Canvas
  使用相同的 `DrawPayload::Text::baseline_y`，但其浏览器字体绘制仍是独立实现。
- `tela-text` 的公开边界只有无状态度量器、覆盖事件和由同一事件归纳的 `GlyphInkBounds`；它不拥有
  纹理、图集、Canvas 上下文、clip 栈或任何 `UiTree` 状态。renderer 只决定如何裁剪、混合和缓存，
  不得自行重新解释字体、em、折行或基线坐标。
- **度量必须是"同一不可变字体数据"的纯函数**：各后端必须挂载同一字体文件，禁止平台原生字体度量，保证跨环境布局一致（见 [009-多环境集成](009-多环境集成.md)）。
- 核心（`tela-core`）不直接依赖字体 crate：度量经 `TextMeasurer` 参数注入；`tela-fonts` 只持有
  名称和字节，`tela-text` 是受控字形的纯实现层（见 [002-架构总览与分层](002-架构总览与分层.md) 4）。

### 4.1 系统约束：字符集与编码

- **文本一律 UTF-8 编码**：外部输入进入基座前统一转为 UTF-8；构建期校验拒绝非 UTF-8 输入。
- **字形与度量只保证中文 + 英文**：基座对中英文范围内的字形、度量与渲染提供确定性保证；超出该范围（其他书写系统）的字符**不做保证**，由上层/宿主决定降级、替换或缺字处理，基座不得崩溃。
- 该约束属系统约束，全环境（wgpu / canvas / raster）一致生效，跨环境文本布局与渲染保持一致。

### 4.2 绝对文字基线协议

`TextMetrics.first_baseline` 表示首行基线相对文本布局盒顶端的逻辑距离。resolve 将它变换为 `DrawPayload::Text { baseline_y }` 的绝对逻辑坐标；之后 Canvas、软件 raster 和 WGPU 都必须直接按该值放置字形，不得各自以 `geometry.y + font_size`、本地 ascent 或图标尺寸重新猜测垂直原点。

这样布局对齐与实际绘制共享同一条基线。后端可以在局部纹理坐标中换算该值，但换算必须可逆且不得改变 `UiFrame` 的绝对语义。

### 4.3 墨迹溢出与裁剪

`DrawCommand::geometry` 是布局盒，不是文字的默认裁剪盒。受控图标字体、重音字形等可以在基线两侧自然溢出该盒；Raster 直接混合共享覆盖事件，WGPU 用 `GlyphInkBounds` 分配紧贴墨迹的纹理并将 quad 平移到真实像素范围。两条后端都只按命令的预合并**祖先** `clip` 与画布边界裁剪文字墨迹，因此不会裁掉 `hero.png` 等行内图标的顶部轮廓。

## 5. 扩展机制

- 自定义特殊视觉效果：通过扩展命令变体接入（`DrawCommand::Custom(Box<dyn CustomDraw>)`）。
- 自定义命令在实现 `FrameSink` 的后端上生效；不支持该效果的后端按能力集降级为兜底绘制（可配置为"跳过"或"绘制占位"）。
- 降级是硬约束：任何扩展命令都必须提供兜底行为，否则在弱环境会崩溃（违反 PRD 一-4）。

## 6. 三个目标后端

| 后端 | 消费端 | 说明 |
|---|---|---|
| `tela-render-raster` | 离线渲染、单元测试、截图输出 | 软件光栅，仅测试/CI/离线/服务端（实现方案见 7）：像素确定性、无 GPU、纯 CPU 无头、no_std |
| `tela-render-wgpu` | 游戏引擎内嵌、3D 世界贴图、浏览器 WebGPU | 高性能，经 wgpu 提交；浏览器经 wasm-bindgen glue（见 6.1） |
| `tela-render-canvas` | 浏览器（wasm） | 基于画布完整渲染页面 |

三者共享 `FrameSink` 与能力集约定；新增后端只实现命令翻译与能力上报，不改核心。

### 6.1 wgpu 后端能力集（2026-08 落地，决策 D43）

| 能力 | 实现 |
|---|---|
| 矩形/圆角矩形 | SDF 片段着色器；`fill=None + border=Some` 编码为透明内部和真实描边宽度，不能降级为实心填充 |
| 圆/椭圆 | SDF（`fs_circle`，椭圆 = 归一化拉伸圆） |
| 描边 | 四边独立四边形 |
| 文字 | `tela-text` 覆盖事件与 `GlyphInkBounds` → 紧贴墨迹的透明 RGBA8 字形纹理 → 既有 image pipeline；纹理签名包含文本、墨迹范围、局部基线、折行宽度和 dpi |
| 裁剪 | 命令级预合并 clip → `set_scissor_rect`（顺序即 z 序，scissor 状态按序切换） |
| 线性渐变 | 256 像素色带纹理 + 顶点渐变轴坐标（独立批次，保留命令声明的色标） |
| 径向渐变 | **降级**：首断点纯色 |
| 阴影 / 多边形 / 图片 / 九宫格 | **降级**：丢弃/跳过（能力未接，demo 未用） |

顶点：SDF 顶点（pos/uv/color/param 四属性）与基础顶点（三属性）两种布局；
渐变另用 pos/t 两属性；四条管线（sdf/circle/text/gradient），文字与渐变带纹理 bind group。
文字栅格化与度量器/软光栅共用 `tela-text` 的字体选择、em 缩放、折行与基线规则；WGPU 只把
绝对 `baseline_y` 换算成纹理局部坐标，不得钳制或重估该值（007-4.0）。

浏览器集成：`cargo build --target wasm32-unknown-unknown -p tela-demo --features webgpu`（release，
wasm-bindgen CLI 需要优化后 wasm）→ `wasm-bindgen --target web` 生成 `tela_demo_gpu.js` glue。
`web/src/main.ts` 只负责选择宿主后端：CPU 与 wgpu 都从同一个 `App::tick_frame` 获取 `UiFrame`，
因此场景构建与布局不会分叉。构建入口为 `ops build all --gpu`。

## 7. tela-render-raster 软件光栅实现方案

### 7.1 定位

- 仅面向**测试/CI/离线导出/服务端**，不做线上高性能渲染。
- 不追求运行性能，优先保证：**像素确定性、无平台差异、无 GPU 依赖、纯 CPU 无头运行**。
- 作为**基准渲染器**：wgpu/canvas 线上渲染以其为对齐标准，作为问题复现基准。
- 高开销特效统一降级，降低开发与 CI 耗时。
- 依赖：`std` 路径为 `tela-contract` + `tela-text` + 基础 2D 数学；无窗口、无系统图形 API、无浏览器 API。`no_std` 路径使用独立 `font8x8` 位图降级。

### 7.2 依赖边界与唯一接口

- 依赖边界：仅依赖 `tela-contract`（`UiFrame`/`DrawCommand`/`LayoutBox`/`ClipRect`）与字形/数学库；**禁止反向依赖 `tela-core`**，输入只接收 `UiFrame`，不参与布局计算。

```
pub fn render_frame(frame: &UiFrame, cfg: RasterConfig) -> BitmapRGBA8
// 1. 创建空白画布
// 2. 遍历有序 DrawCommand（树序=z序，后画覆盖前）
// 3. 单条指令按 BackendCapabilities 降级绘制
// 4. 返回 RGBA8 一维像素缓冲，可直接导出 PNG
```

`RasterConfig`：`dpi_scale`（统一缩放系数，对齐 wgpu/canvas）、`backend_caps`（能力集）、`background`（画布底色）。**逻辑画布尺寸取自 `UiFrame.viewport`**，不再由配置重复传入，消除人为配错（见 [003-场景树与节点模型](003-场景树与节点模型.md) 7）。

### 7.3 单指令执行流程

1. 读指令自带 `clip_rect`，无裁剪取完整画布；
2. 几何图元与裁剪矩形求交，交集为空直接跳过该指令；文字以祖先 clip/画布裁剪共享字形墨迹，不以自身布局盒二次裁剪；
3. 按图元类型分支绘制：矩形/圆角/文字/图片/九宫格/线性渐变；
4. 高开销项降级：blur 阴影→丢弃仅绘本体；径向渐变→起始纯色；复杂多边形蒙版→clip 矩形裁剪；
5. 像素写入仅作用于交集区域，严格按统一 f32 取整规则（见 7.6）。

### 7.4 文字渲染

- 全局固定子集字体二进制经 `tela-fonts` **内嵌**：`tela-ui` 为 WQY 中文正文字体，`tela-icons`
  为 Material Symbols Rounded 图标子集（来源与许可证见 `assets/fonts/`）；raster 按 `FontRef`
  选择并缓存解析结果，不读取系统字体；
- 度量复用与 `tela-core` 同一套 ab_glyph 纯度量逻辑（同一内嵌字体 + em 缩放）；
- `ab_glyph_rasterizer` 生成灰度字形，叠加文本颜色写入画布；
- 文字布局盒与墨迹边界分离：图标等字形可以溢出布局盒，只有命令级祖先 clip 才裁剪它；
- 缺失字符统一渲染实心方块，不崩溃、不打乱布局；
- 完全不依赖平台文字接口，CI 无头环境稳定运行。

### 7.5 四大使用场景

1. **CI snapshot 测试**：输出标准 RGBA8 位图 + PNG 导出工具；像素对比工具（可忽略微小误差阈值、输出差异掩码图）；渲染全程无随机/时钟/系统状态，同一 `UiFrame` 每次输出像素完全一致；no_std 可在轻量 CI 容器编译运行。
2. **离线工具**（文档截图、UI 预览导出）：独立二进制读取序列化 `UiFrame` 文件批量导出 PNG；支持自定义画布尺寸、透明/纯色背景。
3. **服务端批量生成 UI 贴图**：纯 CPU 无窗口后台运行；输出内存位图缓冲直接编码下发，无需落地文件；限制单张画布最大尺寸防内存暴涨。
4. **问题复现（线上基准）**：统一几何取整/裁剪/文字规则作为判定标准；wgpu/canvas 截图与 raster 不一致判为线上渲染 bug；支持单条 DrawCommand 单独渲染，快速定位错位图元。

### 7.6 统一像素取整规范（跨后端 1px 基准）

- 布局全程保留 f32 坐标，不在布局阶段取整；
- raster 光栅阶段统一一套取整规则（四舍五入对齐像素网格）；
- wgpu/canvas 后端**强制复用同一套取整工具函数**，以 raster 输出为基准；
- 所有绘制坐标、clip 矩形、字形位置共用同一数学工具库，消除环境差异。

### 7.7 内置能力集（A10 固化）

raster 内置固定 `BackendCapabilities`，不可开启高耗特性：

- ✅ 支持：纯色矩形、圆角矩形、线段、基础多边形、线性渐变、文字、九宫格、矩形 clip、图片纹理；
- ❌ 不支持（自动降级）：高斯内外阴影、径向渐变、复杂自定义蒙版、子像素精细渲染；
- 降级逻辑写在命令预处理阶段（**raster 后端本地行为**，见 3），渲染层无需额外分支。

### 7.8 工程与 CI

- crate feature：`std`（本地离线工具/服务端，支持文件 PNG 导出）；`no_std`（CI 单元测试，关闭文件 IO，仅内存位图）。
- CI 约束：布局/交互单测必须附 raster 快照校验；快照差异超过阈值直接阻断 MR。
- 性能取舍：CI 不追求极速（每张几 ms~几十 ms 可接受）；不做 Atlas 字形缓存优化（线上 wgpu/canvas 才做），简化代码。

### 7.9 明确不做

- 动画帧渲染（仅静态单帧 UiFrame）；
- 图层缓存、局部重绘优化（测试场景不需要）；
- SDF / 矢量高级美化渲染；
- 拖拽、实时交互预览（只做静态输出）；
- 多线程并行渲染（单线程简化，避免内存同步 bug）。

### 7.10 no_std 兼容性预案（工程风险）

该风险已按明确的 feature 边界关闭：`tela-text` 是 `std` 的受控字体解析、度量和覆盖事件层；Raster
的 `no_std` feature 不依赖它，继续使用 `font8x8` 位图字形和确定的缺失方块。因此 no_std 不要求
动态 TTF 解析，但仍保留可离线、可重复的文字降级路径。

## 8. 绘制规则

- ✅ `UiFrame` 只含命令与命中区域，后端不依赖树/布局内部结构。
- ✅ 绘制只消费 `visual` + `content` 维度，几何来自布局输出。
- ✅ 裁剪以命令级预合并 clip rect 表达，后端按 clip 裁剪、不维护裁剪栈（见 2）。
- ✅ 不新增 z-index 数值维度，层级仅由树序（命令顺序）+ `draw_order` 局部重排（同父容器内）+ 页面/模态栈决定。
- ✅ `draw_order` 仅作用于直接父布局容器内，作用域隔离；命中区域顺序与绘制顺序一致（见 [006-布局引擎](006-布局引擎.md) 4.5）。
- 🔧 所有特效（含自定义扩展）必须有降级兜底，否则禁止进入命令集。
- 🔧 文字度量可离线执行，禁止依赖真实字形渲染环境。
- ✅ 受控字形栈：`tela-fonts` 提供同一不可变字体数据，`tela-text` 统一解析/度量/定位与覆盖事件；Raster/WGPU 消费同一结果（见 4.0）。
- ✅ 系统约束：文本一律 UTF-8，字形/度量只保证中英文；超出字符集不崩溃、由上层降级（见 4.1）。
- ✅ 像素取整统一规范：布局 f32 不取整；raster 统一取整，wgpu/canvas 复用同一取整工具函数，以 raster 为基准（见 7.6）。
- ✅ raster 内置固定能力集：高耗特效（高斯阴影/径向渐变/复杂蒙版/子像素）统一在命令预处理阶段降级（见 7.7）。
- 🔧 命令顺序即 z 序，后端不得重排。
