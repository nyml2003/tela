# 010-落地路线

> **当前落地状态（与源码一致，失真即改）**：M0 契约与工程骨架、M1 树与纯操作 resolve、
> M2 布局引擎（Flex+wrap/Stack/ScrollView/三层尺寸解析/测量缓存）、M3 绘制命令与软件光栅后端、

> `tela-render-canvas`（Canvas2D 抽象 + 命令翻译）与 `tela-demo`（CPU/WGPU wasm 演示页）已提供。
>
> **边界说明（已解决项见 [016-已解决问题归档]）**：core 已提供 `BindId`/`ValueChange` 契约、
> 基础文本输入宿主桥接，以及 `InteractConcern.modal`/`text_input` 字段；通用绑定编排、IME

> raster 阴影无模糊（能力集默认关闭）；网格 Grid、变高虚拟列表、`LayoutBoundary` 见 [011]。

## 1. 原则

- **先核心后环境**：渲染器无关的核心全部可在无窗口环境验证，先做核心 + 软件光栅，再接 wgpu / canvas。
- **纯核心优先**：树、布局、绘制、交互保持确定、可测试；窗口、文件、网络、真实时间留在宿主外壳。
- **文档失真即改**：实现与本文档冲突时，在同一变更中更新文档。
- **每阶段有验收**：见各里程碑验收判据。

## 2. 里程碑

### M0 — 契约与工程骨架

- 建立 Rust workspace：`tela-contract`、`tela-core`、`tela-render-raster`，顶层 `flake.nix` 开发环境。
- 定义纯类型契约：`UiNode`/`NodeKind` 与五维度槽位（`LayoutConcern`/`VisualConcern`/`InteractConcern`/`IdentityConcern`/`ContentConcern`）、`Constraints`/`LayoutBox`/`UiFrame`（含 `viewport`）/`DrawCommand`/`HitRegion`/`ClipRect`、尺寸类型（`Size`/`BaseSize`/`MinMax`）、`TextMetrics`/`TextMeasurer` trait、`BackendCapabilities`、`BindId`/`UiAction::ValueChange`、`KeyCombo`/`ShortcutId`/`RawKeyboardEvent`/`UiAction::ShortcutActivated`、`Viewport`/`ScrollState`/`SemanticKey`、`UiAction`/`HostPorts`/`KeyStrategy`/`UpdateMode`。M0 只做类型/枚举/结构体定义，不实现业务逻辑。
- 基线编码规则：核心 `forbid(unsafe)`、依赖方向检查、类型化错误、无 panic 索引。

**验收**：workspace `cargo check`/`test` 通过；契约 crate 零依赖；无窗口环境可构建。

### M1 — 树与纯操作 resolve

- 值语义 `UiNode` 树（五维度槽位）、构建期校验（id/key 唯一、非零基数）、`resolve` 纯操作输出 `UiFrame`（命令 + 命中区域）。
- 构建器约束：逻辑容器构造不出 `layout`/`visual`；布局容器必须带 children；原语要求 `content`。
- `auto-path` 默认身份策略（先实现最简单的）。

**验收**：同树同 viewport 必同帧（单测）；非法树返回结构化错误；`resolve` 不读时钟/随机/输入；**正交性独立性测试**——改 `visual` 布局输出不变、改 `layout` 绘制内容类型不变；逻辑容器无法设置几何字段（编译期验证）。

### M2 — 布局容器（Flex + wrap → Stack）

- `LayoutEngine` trait + `Constraints`；先 Flex（含 wrap 开关），最后 Stack。
- **单节点测量缓存**（路线 A）：`Constraints → 自身尺寸` 查表，纯输入失效判定，仅改 measure 函数（见 [004-更新策略与状态保持](004-更新策略与状态保持.md) 7.1）。
- 统一 Flex + wrap 开关（路线 B）：`wrap=false` 单行全局 Fill；`wrap=true` 自动换行、Fill 仅单行内部、跨行不共享空白；废除独立 Flow 容器。
- 尺寸模型（`BaseSize`/`MinMax` 修饰包装器，三层解析：基准 → 本地钳制 → 父 Constraints 二次钳制）、盒模型、Stack 堆叠（Content/FillOverlay 语法分层，同盒树序 + 边角对齐）、溢出与滚动；**首版不实现相对/绝对定位**；栅格 Grid 暂不支持（未来扩展）。
- 盒尺寸违反最小约束返回 `UiLayoutError`；`FillOverlay` 越界使用、MinMax 非法写法（包裹 Fixed/min>max/嵌套）、非法尺寸搭配均构建期报错。
- 裁剪以命令级预合并 clip rect 表达（滚动/裁剪容器祖先求交）。
- 虚拟列表不在此里程碑：它依赖 `semantic-id` 与视图状态仓库，随 M4 落地。

**验收**：两种容器单测覆盖尺寸/约束/堆叠/溢出；同节点同约束同盒子；MinMax 三层解析（基准→本地钳制→父约束）各分支单测、非法写法构建期报错；Flex `wrap=false` 单行 Fill 均分、`wrap=true` 自动换行且 Fill 仅单行内生效（跨行不共享空白）；Stack Content/FillOverlay 尺寸隔离与边角对齐正确、`FillOverlay` 越界构建期报错；滚动 offset 由外部输入提供（构造任意 `scroll_inputs` 可测）、嵌套滚动/裁剪容器每条命令 clip rect 为祖先求交；跨帧记忆滚动位置归 M4；**测量缓存同输入同输出、清缓存不影响结果**。

### M3 — 绘制命令与软件光栅后端

- 全部绘制原语命令化：矩形/圆角/圆/椭圆/多边形/图片/文字/九宫格/渐变/阴影/蒙版。
- 局部 DrawOrder（`VisualConcern.draw_order`）：同父容器内分组（InnerBottom → Normal → InnerTop）+ 组内权重升序 + 树序兜底排序，绘制与命中序列一致（见 [006-布局引擎](006-布局引擎.md) 4.5）。
- 文字栅格化：`ab_glyph`（解析/度量）+ `ab_glyph_rasterizer`（覆盖蒙版）；`TextMeasurer` 基于 ab_glyph，各后端挂载同一字体文件。
- `FrameSink` trait + `BackendCapabilities` + 声明式降级。
- `tela-render-raster`：`render_frame(frame, RasterConfig) -> BitmapRGBA8` 唯一入口，逻辑画布尺寸取自 `UiFrame.viewport`；软件光栅，仅测试/CI/离线/服务端；`std`/`no_std` feature（no_std 兼容性预案见 [007-绘制与渲染后端](007-绘制与渲染后端.md) 7.10）；统一 f32 取整规范（布局不取整、raster 取整、线上后端复用同一取整工具）；内置能力集固定（高斯阴影/径向渐变/复杂蒙版/子像素降级，降级为后端本地行为）；内嵌 Noto 子集字体 + `ab_glyph_rasterizer` 栅格化；PNG 导出与像素对比工具。

**验收**：raster 后端可渲染一棵复杂树（含文字、滚动裁剪）为位图；同一 UiFrame 像素确定性可复现；不支持特效按能力集降级不崩溃；snapshot 测试通过 + 差异超阈值阻断；no_std 无窗口构建运行；clip rect 裁剪正确（滚动容器内容不外溢）；取整规则与线上后端一致；draw_order 排序正确（分组/权重/树序兜底，命中顺序与绘制一致）。

### M4 — 身份策略、视图状态与虚拟列表

- `auto-stable-identity` 身份分配算法（内容指纹 + 延迟回收）、`semantic-id`、`manual`。
- `ViewStateStore`（焦点/光标/滚动/选中/弹窗）随 key 匹配复用/回收。
- 虚拟列表：可视区渲染 + 滚动定位，**首版仅支持定高 item**（变高后续扩展，变高落地时配独立 item 尺寸缓存池、以 `semantic-id` 为 key，见 [004-更新策略与状态保持](004-更新策略与状态保持.md) 7.3），item 必须显式 `semantic-id`（依赖本里程碑的身份与视图状态能力）。
- 开发环境重复 key 与策略误用检测告警。

**验收**：插入/删除/重排/类型切换/销毁回收的稳定身份单测；状态随 key 保持；虚拟列表缺 `semantic-id` 构建期报错；跨滚动 item 状态由业务数据承载。

### M5 — 更新策略（整体重建 / 局部 Dirty）

- 容器级策略配置向下生效、子容器覆盖；Full 全量重布局，Dirty 脏子树标记局部重算。
- 组件无感知：同一组件代码两种模式可运行。
- 禁止运行时频繁切换（开发期告警）。

**验收**：Dirty 子树下仅脏节点重算（可测布局调用次数）；Full/Dirty 渲染结果一致；组件无感知单测。

### M6 — 交互、焦点与模态

- 输入事件 → 命中测试（含滚动坐标换算、模态拦截）→ `UiAction` 出站。
- 焦点系统为规约式状态转移（组件树 + 焦点图，**无空间导航**）：
  - 标准容器（列表/ScrollView/Stack）自动生成焦点转移规则；网格容器焦点逻辑属未来扩展（Grid 首版不支持）；
  - 默认父子/兄弟树关系导航；**边界穿越默认回退父作用域按树序解析**（父零配置）；
  - 业务显式局部规约（禁用跳转、强制落点）采用**替换覆盖语义**：存在显式规约时替换该 `(节点, 输入)` 的所有自动规则，单输入唯一目标；无显式规约才走自动跳转 → 默认回退；
  - 取消键：焦点在模态子树内**先关当前模态**，否则沿树回退到最近焦点组出口；确认触发主动作。
- 双焦点模型（PC Tab / 主机方向键）共享焦点作用域树，焦点状态入视图状态仓库。
- FocusScope **方向化** entry/exit 端口契约：`entry_*`/`exit_*` 按方向绑定、方向无关简写、解析顺序（方向端口→默认端口→首个可聚焦）、父图静态隔离检查、`unsafe_internal_ref` 逃逸口子（Linter 警告）。
- **Teleport 焦点迁移**：Teleport 子树焦点链迁移至 ModalHost 目标 Scope，按渲染序参与 Tab；semantics 保留原始位置（对齐 Flutter Overlay）。
- **绘制/焦点解耦**：DrawOrder 不改焦点遍历；`tab_index`（InteractConcern 整数，-1 移出序列）独立调 Tab 序。
- **FocusTrap 底层原语**：`FocusScope.trap_focus` Scope 内 Tab/Shift+Tab 循环；ESC/点击外部/自动聚焦/关闭恢复由上层 `tela-widgets` FocusTrap 封装。
- **Save/Restore 焦点**：`UiAction::SaveFocus`/`RestoreFocus` 显式原语，无自动隐式恢复。
- **键盘与快捷键**：`RawKeyboardEvent` 从焦点节点沿 FocusScope 冒泡；`ShortcutScope`（逻辑容器）内 `KeyCombo → ShortcutId` 映射、consumed 终止冒泡、跟随 Teleport 迁移、局部键位覆盖；core 输出 `UiAction::ShortcutActivated(id)`；全局快捷键归宿主/adapter（直接监听原始事件）；Esc 映射 `ShortcutId::ESCAPE`、关闭逻辑上层实现。
- 嵌套模态栈拦截下层输入。

**验收**：合成事件驱动单测断言 `UiAction` 序列与焦点转移；**焦点转移纯函数可离线推导**（不读布局/时钟，可枚举合法下一焦点）；边界处默认回退树序解析可离线推导；**任一 `(节点, 输入)` 目标唯一**（显式规约替换自动规则后无多候选歧义）；方向化端口按方向落点正确（从上进入落首项、从下进入落末项）；取消键在模态内关模态、在模态外回退最近焦点组出口；父图引用子 Scope 内部 id 构建期报错；`unsafe_internal_ref` 触发 linter 警告；entry 绑定节点销毁降级到该方向次选/首个可聚焦节点；**Teleport 子树可正常 Tab 进入/退出（焦点链迁移）**；**DrawOrder 提升不改 Tab 顺序、tab_index 生效**；**trap_focus 首末项回绕且不跳出 Scope**；**Save/Restore 显式调用可恢复焦点**；**快捷键：焦点内 ShortcutScope 命中输出 ShortcutActivated、consumed 终止冒泡、Teleport 迁移后仍生效、全局快捷键宿主实现**；模态栈遮挡验证；开发期检测对"视觉序 vs 焦点序"偏差告警。

### M7 — 多环境集成

- `tela-render-wgpu`：嵌入渲染 + 贴图输出路径。
- `tela-render-canvas`：浏览器 wasm，基于画布完整渲染页面。

## 3. 上层扩展（首版核心不依赖）

以下能力作为**上层业务组件套件**的标准分层方案，建立在一套根节点 + 逻辑容器之上，首版核心不实现、不依赖；核心只需提供树序堆叠、模态栈与逻辑容器（FocusScope/IdentityScope/ModalHost）。

### 3.1 页面堆栈（ModalHost 页面栈）

> 分层澄清：`ModalHost` **容器本身**由核心契约提供（M0 定义：模态遮罩、子节点层级排序、点击外部关闭等基础能力）；**页面栈、多路由压栈/弹出管理逻辑是上层业务组件**，不属于内核（见 [003-场景树与节点模型](003-场景树与节点模型.md) 2）。

根下 `ModalHost` 逻辑容器维护页面栈数组，替代全局 z-index 分层：

- 栈元素存页面根节点 key、打开快照、焦点备份；入栈 push 生成独立顶层子树，出栈 pop 销毁并恢复上一层焦点。
- 渲染规则：栈从底到顶依次遍历生成绘制命令，栈顶页面天然全局最上，无需任何层级数值。
- 适用：多页面路由、弹窗页面、浮窗面板、游戏多级菜单；每层页面是独立子树，天然隔离堆叠，下层元素不会窜到上层。

### 3.2 Scope Context（类 Context 的静态上下文）

依托现有 `FocusScope`/`IdentityScope` 逻辑容器做**静态编译期上下文**注入，不做运行时动态订阅：

- 承载内容：局部堆叠分组标识、局部滚动上下文、局部输入拦截规则。
- 传递规则：Scope 内所有后代节点自动继承，子 Scope 可覆盖。
- 局部堆叠隔离：同一 Context Scope 内部仅靠子树顺序控制层级；Scope 之间按页面栈顺序整体分层，内部不会穿透到外部。

### 3.3 组合工作流示例

```
ModalHost（页面堆栈根）
 ├─ PageScope(首页上下文，栈底层)
 │  ├─ 表格、表单（树序靠后元素上浮）
 │  └─ TooltipScope（局部上下文，放在同 Scope 末尾，盖住表格）
 └─ PageScope(编辑弹窗，栈顶层，整层盖住首页)
    └─ 弹窗内部按钮、输入框
```

- 页面栈保证「弹窗整层高于首页」；单页面内靠子节点书写顺序实现按钮浮在背景上；局部 Tooltip 放在同 Scope 末尾盖住内容；多层弹窗直接入栈自动逐层覆盖。

### 3.4 未来扩展

- `Grid` 栅格容器（行列轨道、跨行跨列）、变高虚拟列表：首版暂不支持，后续按需补充。
- `LayoutBoundary` 布局边界容器（v1.1）：边界内整棵子树完整 LayoutBox 按 key 缓存，脏标记不穿透外层（对标 Flutter RelayoutBoundary / GPUI），见 [004-更新策略与状态保持](004-更新策略与状态保持.md) 7.2；变高虚拟列表落地时配独立 item 尺寸缓存池（`semantic-id` 为 key）。
- `FreeCanvas` 自由画布容器或局部绝对定位（强制绑定定位上下文），见 [006-布局引擎](006-布局引擎.md) 4.3。

### 3.5 编辑器差异化约束（DrawOrder）
基座完整保留带权重的 DrawOrder（v1 能力，见 [006-布局引擎](006-布局引擎.md) 4.5），全环境统一、不单独裁剪底层；编辑器上层按需二选一实现定制约束：

- **方案 A**：封装自定义 `EditorLayer` 逻辑容器，业务完全不用 `draw_order`，上层提前按业务图层 z 值排好节点顺序，基座仅用默认 Normal；
- **方案 B**：编辑器宿主增加构建期校验，拦截带自定义权重的 DrawOrder，强制仅使用无参三档枚举（InnerBottom/Normal/InnerTop）。
- 编辑器渲染层可自定义 `FrameSink` 后置重排 `DrawCommand`，实现海量图层自由分层，复杂渲染逻辑由上层接管。

### 3.6 上层组件与业务数据绑定（tela-widgets / tela-ui）

基座只提供契约（`BindId` 挂 `InteractConcern`、`UiAction::ValueChange`，M0 定义）。`tela-widgets`
保留 `Button`/`Input`/`Checkbox` 等原子控件、受控值和 IME 宿主适配；`tela-ui` 承担
`Form`/`Table`/`Select`/`Cascader`/`Toolbar` 等组合模式，并以 `UiIntent` 向宿主表达命令意图。
响应式运行时与双向同步仍在宿主侧（自定义 Signal、统一 `BindId`/`UiIntent` 分发、`build()`
驱动刷新）；core/adapter 禁止引入订阅/观察者/Effect 响应式运行时（完整方案见
[012-业务数据绑定](012-业务数据绑定.md) 和 [015-tela-ui 与局部交互状态](015-tela-ui与局部交互状态.md)）。

## 4. 优先级注记

- M1–M3 是核心价值，必须先落地。
- M4（身份 + 视图状态 + 虚拟列表）完成数据驱动渲染闭环，M5（更新策略）实现局部高效更新，紧随其后。
- M6/M7 依赖前面所有里程碑，最后接入。
- 任一后端（wgpu / canvas）可在核心稳定后独立推进，互不阻塞。

## 5. 每阶段通用验收

- 代码通过 `cargo fmt --check`、`cargo clippy`、`cargo test`。
- 新增能力附单测；确定性可离线复现。
- 文档与实现一致，失真部分在同一变更内更新。
