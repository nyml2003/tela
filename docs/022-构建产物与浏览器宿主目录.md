# 022-构建产物与浏览器宿主目录

> **状态：✅ 已实现。** 本文定义浏览器 WebView 壳、应用 guest、原生开发 SDK 与静态发布目录的物理边界。

## 1. 结论

仓库不再使用 `demo/` 目录，也不再让浏览器直接加载一份专用的 `tela-demo.wasm`。可编辑源码与可删除构建产物严格分离：

```text
crates/
├── tela-demo/               文件管理器应用 guest（`app-wasm`）
├── tela-app-abi/            guest 与所有壳共享的版本化事件/帧协议
├── tela-bundle/             .tela archive 与完整性清单
├── tela-webview-sdk/        浏览器 WebView Rust/WGPU 胶水壳
├── tela-win32-sdk/          Win32 开发壳源码
├── tela-macos-sdk/          macOS AppKit/Metal 开发壳源码
└── tela-native-sdk-runtime/ 原生壳共用的 bundle/Wasmtime/lifecycle runtime
web/
├── public/                  可编辑 HTML 模板
└── src/
    ├── main.ts              薄启动入口
    ├── webview-sdk/         DOM 输入、bundle 加载与 WebView 生命周期
    └── rawgpu.ts            独立的原生 WebGPU 环境诊断
ops/
└── src/                     构建、校验与静态服务用例
dist/                         Git 忽略；仅允许构建产物
```

`dist/` 不承载源码、文档、手写脚本或独立实验 crate。删除整个目录后，项目必须能仅通过受控构建命令恢复全部内容。

## 2. 统一启动链

浏览器不是 ABI 的旁路实现。它与 Win32/macOS 壳加载同一份 `.tela`，差别只在 guest 的执行器和窗口/输入适配：

```text
index.html + app.js
  -> tela_webview_sdk.js / _bg.wasm          固定 WebView WGPU 壳
  -> GET /tela-dev/latest.json (no-store)
  -> GET /tela-dev/tela-demo.tela (no-store)
  -> Rust 校验 archive / SHA-256 / ABI
  -> 浏览器原生 WebAssembly 实例化 app.wasm
  -> AppEvent <-> AppStatus / UiFrame
  -> tela-render-wgpu -> HTMLCanvasElement
```

浏览器 guest 使用 WebAssembly API，因此没有 Wasmtime 的 fuel 限额；`tela-webview-sdk` 仍在 Rust 中负责 bundle 格式、哈希、ABI、帧解码和 WGPU 渲染，以避免 JavaScript 复制协议实现。产品页只使用 WGPU。`rawgpu.html` 仍是独立环境诊断页，它不装载 tela 应用、bundle 或 renderer。

默认索引是相对当前页面解析的 `/tela-dev/latest.json`。页面与 bundle 可以同源；开发服务器也只为 `/tela-dev/*` 返回 `Access-Control-Allow-Origin: *`，便于受控的跨机器开发，不给其他静态资源开放跨域读取。

## 3. 产物组成与来源

完整构建后，`dist/` 的每项都有唯一来源：

| `dist/` 项 | 来源 | 生成者 |
| --- | --- | --- |
| `index.html` | `web/public/index.html` | `web/build.mjs` |
| `rawgpu.html` | `web/public/rawgpu.html` | `web/build.mjs` |
| `assets/tela-web/app.js` 与 source map | `web/src/main.ts`、`web/src/webview-sdk/` | esbuild |
| `assets/tela-web/rawgpu.js` 与 source map | `web/src/rawgpu.ts` | esbuild |
| `tela_webview_sdk.js`、`.d.ts` | `crates/tela-webview-sdk` | wasm-bindgen |
| `tela_webview_sdk_bg.wasm`、`.d.ts` | `crates/tela-webview-sdk` release wasm | wasm-bindgen |
| `tela-dev/tela-demo.tela` | `tela-demo` 的 release `app-wasm` + `assets/` | `ops build bundle` |
| `tela-dev/latest.json` | archive 的 SHA-256、ABI、URL 与大小 | `ops build bundle` |
| `win32/tela-win32-sdk.exe` | `crates/tela-win32-sdk` GNU Windows target | `ops build win32` |
| `macos/Tela.app/Contents/Info.plist` | `crates/tela-macos-sdk/resources/Info.plist` | `ops build macos` |
| `macos/Tela.app/Contents/MacOS/tela-macos-sdk` | `crates/tela-macos-sdk` aarch64 macOS target | `ops build macos` |

浏览器在发布根装载固定 shell：`/tela_webview_sdk.js` 和 `/tela_webview_sdk_bg.wasm`；应用 guest 只能从经索引引用的 archive 内取得。这样 `ops serve` 只需以 `dist/` 作为静态根，无需路径重写。

## 4. 构建与所有权

`ops build` 与 `ops build all` 都是默认发布组合：先删除并重新创建由工作区路径模型推导出的 `dist/`，再依次生成 WebView WGPU shell、前端静态文件与 `tela-dev` 开发包。完整构建不会留下上一次构建的陈旧文件。

单目标构建不清空 `dist/`：

- `ops build webview` 只写 release WGPU shell 和 wasm-bindgen glue；
- `ops build frontend` 只重建 `assets/tela-web/` 并复制 HTML 模板；
- `ops build bundle` 只写 `tela-dev/`，先完成临时 archive 与 guest 校验，再原子发布 `latest.json`；
- `ops build win32` 只写 Win32 开发壳；
- `ops build macos` 只在 Apple Silicon macOS 写 `Tela.app`，不把远程应用 bundle 嵌入 App；
- `ops verify bundle` 校验已发布 `.tela` 的 archive、ABI 与 guest 首帧；`--build` 先生成 bundle；
- `ops verify gpu` 只构建并服务 `rawgpu.html`，等待人工打开页面上报原生 WebGPU 三角形回读；它不启动浏览器，也不验证 tela renderer。

完整构建是唯一允许重置 `dist/` 的命令。文件系统删除经过 `FsPort.resetDir`，且目标只能是 `WorkspacePaths.distDir`，避免构建逻辑散布任意递归删除。

## 5. 删除的遗留边界

以下旧边界已经删除，不能再作为新代码或验收依据：

- 浏览器直载 `dist/tela_demo.wasm` 的 CPU demo；
- `tela_demo_gpu.js` / `_bg.wasm` 与 `tela-demo` 的 `webgpu` feature；
- 产品页的 `?backend=raster|wgpu|auto` 选择与 CPU 回退；
- `ops build demo`、`ops build ... --gpu`、`ops verify demo` 与 Node wasm smoke adapter。

软件 raster 仍是测试、CI、离线和问题复现基准；它不再是浏览器产品页的运行时回退。保留 `rawgpu.html` 是为了将浏览器/WebGPU 环境问题与 tela WGPU 渲染问题分开诊断，而不是重建第二个产品后端。

## 6. 验收

```bash
ops check
ops build
ops verify bundle
ops build win32
ops build macos # 仅 Apple Silicon macOS
ops serve
git check-ignore -v dist/index.html
git ls-files dist
```

`ops serve` 只报告 URL，不启动浏览器。最后一条应无输出，说明 `dist/` 没有被版本控制；前一条应显示根 `.gitignore` 的 `/dist/` 规则。不通过手工复制、编辑 `dist/` 或保留旧 demo wasm 文件来满足验收。
