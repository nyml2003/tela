# 006-布局引擎

## 1. 布局能力总览

| 能力 | 说明 |
|---|---|
| 两种排版模式 | 弹性 Flex（含 wrap 换行开关）、堆叠 Stack（栅格 Grid 暂不支持，见 4.3） |
| 尺寸模型 | 固定尺寸、百分比、自动尺寸、填充剩余空间 |
| 约束 | 最小/最大宽高约束 |
| 盒模型 | 内边距、外边距、边框 |
| 层级堆叠 | Stack 同盒堆叠（树序）+ 页面/模态栈顶层子树；**无相对/绝对定位、无 z-index** |
| 内容 | 溢出控制、容器滚动 |
| 长列表 | 虚拟列表，仅渲染可视区域 |

## 2. 布局抽象

布局以 `LayoutEngine` trait 抽象，两种布局容器共享同一布局结果格式 `LayoutBox`。

```
Constraints { min_w, max_w, min_h, max_h }
LayoutNode  { layout: LayoutConcern, children }
LayoutBox   { x, y, w, h, children }
```

- 布局引擎**只消费 `layout` 维度**（`UiNode` 的 `LayoutConcern`，见 [003-场景树与节点模型](003-场景树与节点模型.md)），不读取 `visual`/`interact`/`identity`。
- `LayoutEngine::measure(node, constraints) -> LayoutBox`：纯函数，输入节点与约束，输出盒子树；measure 结果可做**单节点测量缓存**加速（纯输入查表，见 [004-更新策略与状态保持](004-更新策略与状态保持.md) 7）。
- 引擎可组合：Flex/Stack 可互相嵌套。
- 布局结果（`LayoutBox` 树）与绘制解耦，绘制层只消费盒子几何。

### 两种布局容器

| 容器 | 语义 | 适用 |
|---|---|---|
| Flex | 单轴弹性，`wrap` 开关控制换行（见 2.1） | 工具栏、弹窗头布局、侧边栏分栏、标签列表、自动折行 |
| Stack | 同盒堆叠，子节点共享同一盒空间，按树序绘制 | 卡片角标、局部悬浮、同盒覆盖 |

> 实现优先级建议：先 Flex（含 wrap 开关）→ Stack，见 [010-落地路线](010-落地路线.md)。

### 2.1 统一 Flex + wrap 开关（决策）

**路线 B 定案**：废除独立 `Flow` 容器，统一为单一 `Flex` 容器 + `wrap: bool` 开关，对齐 Web CSS/Yoga（RN、Unity UI Toolkit）、新版 Jetpack Compose（统一 FlexBox）、Unity UGUI/UI Toolkit 的标准演进方向。

- **行业对标**：强隔离两套容器（单行弹性 Flex / 纯流式无填充 Wrap/Flow）是 Web、Flutter、WPF、老版 Compose、游戏 UI 的**过渡形态**，长期都收敛为"单容器 + 换行开关"；两套隔离容器的痛点（折行 + 单行填充需要多层嵌套 Hack）被各框架社区反复验证。tela 首版无存量代码，直接走标准终态，**零迁移成本**。
- **wrap 语义**：
  - `wrap=false`：单行，全局 Fill 分配剩余空间（原 Flex 逻辑，不换行；内容溢出由外层 `overflow` 控制）；
  - `wrap=true`：自动换行，**Fill 仅作用于单行内部**，跨行不共享剩余空间（对齐 CSS/Yoga，无布局歧义）。
- **构建期校验**：仅限制 `wrap=true` 时 Fill 作用域为本行；不再有"Flow 禁 Fill"的强隔离校验。`Flex(wrap=true)` 的流式能力即原 Flow 全部语义。

| 特性 | `wrap=false` | `wrap=true` |
|---|---|---|
| 自动换行 | ❌（溢出由外层 overflow 控制） | ✅ 自动 |
| Fill 分配 | 全局剩余空间 | 仅单行内部，跨行不共享 |
| 典型用途 | 固定行列、分栏、工具栏 | 标签列表、段落折行、自适应工具栏 |

**边界补充规则**：
1. `wrap=true` 时每行独立计算，Fill 只吃本行空白，跨行不分配（消除歧义，保证跨环境一致）；
2. 需要自动换行一律 `wrap=true`，禁止用嵌套多层 Flex 模拟换行；
3. 首版仅支持水平主轴换行，垂直段落流式后续扩展。

```rust
// wrap=false：单行不换行，Fill 均分/填充空白
Flex(row, wrap = false, [
    Text("左侧"),
    Rect(layout.fill()),   // 填充中间空白
    Text("右侧"),
])

// wrap=true：自动换行，每行内部可 Fill
Flex(row, wrap = true, [
    Tag("标签1"), Tag("标签2"), Tag("标签3"), Tag("标签4"),
])
// 空间不足自动换到下一行，标签宽度固定；若行内有 Fill 元素只吃本行空白
```

### 2.2 首行基线对齐

`CrossAlign::Baseline` 仅在水平 Flex 行生效。每个文本叶子由 `TextMeasurer` 返回从布局盒顶端到首行基线的 `first_baseline`；行容器取最大上行高度并移动子项，使所有参与项的绝对首行基线相同。没有文字基线的子项以盒底作为回退基线，因此普通图元仍有确定行为。

图标字体是文本节点，图标与文字不应依赖组件私有的 y 偏移。带图标的 Button、Toolbar、导航行或品牌行应显式使用 `CrossAlign::Baseline`；外层若还含搜索框、Spacer 等不同语义元素，应把需要对齐的图标和标签包在独立的 Baseline 行中，避免无关子项影响该行。

`LayoutBox.first_baseline` 是布局产物，随文本度量缓存、换行和字号一起重算；它不属于视觉微调或 renderer 推测。

## 3. 尺寸模型

尺寸定义为「原生基准 + 可选约束包装」两层结构，MinMax 是**修饰包装器**而非独立尺寸模式：

```
// 基础原生尺寸基准（无约束修饰）
pub enum BaseSize {
    Fixed(f32),       固定尺寸
    Percent(f32),     占父容器可用空间的百分比
    Auto,             由内容推导（文本、图片、子节点）
    Fill,             填充剩余空间（主轴/交叉轴上的伸展）
}

// 带上下限钳制的修饰包装器
pub struct MinMax {
    pub base: BaseSize,
    pub min: Option<f32>,  // None = 无下限
    pub max: Option<f32>,  // None = 无上限
}

// 顶层尺寸类型：二选一，原生基准 / 带约束包装
pub enum Size {
    Raw(BaseSize),
    Constrained(MinMax),
}
```

### 3.1 三层解析流程（严格顺序）

输入：当前尺寸定义 + 父容器全局 `Constraints(min_w, max_w)`：

1. **基准层计算**：按 `base` 算出原始尺寸 raw_size——Auto 用文本/子内容度量、Fill 分配父容器扣除其他元素后的剩余空间、Percent = 父可用空间 × 百分比、Fixed = 固定数值。
2. **本地 MinMax 钳制**：raw_size 与 `min/max` 裁剪——有 `min` 取 `max(raw, min)`，有 `max` 取 `min(size, max)`；单侧为 None 不做对应限制。
3. **父容器全局约束二次钳制**：上一步结果再与 `Constraints(min_w, max_w)` 取交集，得到最终合法尺寸。

> 两层约束互不覆盖：MinMax 是节点自身局部限制，Constraints 是父容器给该节点的整体可用区间，叠加生效。

演算示例：

- `MinMax{base: Auto, min: 80, max: 240}` + 父 `Constraints(min:50, max:200)`：Auto 内容宽 260 → 本地钳制 240 → 父约束封顶 200 → 最终 200。
- `MinMax{base: Fill, min: 100, max: None}` + 父 `Constraints(min:150, max:600)`：Fill 分配 80 → 本地保底 100 → 父约束下限 150 → 最终 150。

### 3.2 边界规则（构建期强制校验）

1. **禁止 MinMax 包裹 Fixed**：`Size::Constrained(MinMax{base: Fixed(..)})` 非法，构建期 `UiBuildError`（Fixed 已是确定常量，修饰无意义）。
2. **min > max 直接报错**：同时提供 min、max 且 min > max → `UiBuildError`，避免负尺寸。
3. **单边省略对齐 CSS**：`min: Some(60), max: None` = 最小 60 自适应内容；`min: None, max: Some(500)` = 填充剩余但不超过 500。
4. **与 Stack FillOverlay 兼容**：`Size::Constrained(MinMax{base: Fill, ..})` 允许用于 FillOverlay——Stack 先算完整盒 → Fill 铺满 Stack 盒 → min/max 收缩/保底 → 叠加父 Constraints。
5. **不允许嵌套 MinMax**：`MinMax.base` 只能是原生 `BaseSize`，不能再套 `Constrained`，构建期拦截多层约束嵌套。

- 固定与百分比在 measure 阶段解析。
- Auto 需要内容度量：文本走字形度量，图片走资源尺寸，容器走子节点求和。
- Fill 在父约束已知后分配剩余空间。
- 最小/最大宽高约束通过 `Constraints` 传递，任何引擎不得产出越界盒子。

## 4. 盒模型、堆叠与定位约束

- 内边距（padding）参与内容区域计算；外边距（margin）影响兄弟间距；边框（border）计入盒尺寸。其中 border 的**宽度**归 `layout` 维度（参与盒尺寸），border 的**颜色**归 `visual` 维度（不影响盒尺寸）——一字段一维度的拆分示例，见 [003-场景树与节点模型](003-场景树与节点模型.md)。

### 4.1 无相对/绝对定位、无 z-index（标准说明）

> 基座首版不提供相对/绝对定位能力，也不提供独立 z-index 数值维度，所有层级与悬浮效果通过以下**流内**机制实现：
> 1. 页面/模态堆栈（ModalHost）：全局弹窗、遮罩、顶层浮层独立子树，天然全局置顶；
> 2. Stack 布局容器：同一盒内多元素堆叠、边角角标、局部悬浮，完全处于文档流；
> 3. 固定层/滚动内容拆分：固定头部/侧边栏放固定层子树（与滚动内容子树同级、不进入滚动流），或 ScrollView 双层嵌套（外层固定尺寸、内层滚动内容、固定 UI 放外层同级）；
> 4. visual 视觉偏移：不改变布局尺寸的微小位移，用于装饰微调；
> 5. Teleport 逻辑容器：下拉/Tooltip/编辑器悬浮面板/鼠标跟随浮层——portal 不参与父布局，帧生成阶段提升至 ModalHost 顶层队列渲染，锚点/鼠标偏移为纯视觉偏移（见 4.4）。
>
> 所有节点统一参与标准文档流排布，消除脱离文档流带来的复杂定位上下文、坐标换算、滚动偏移逻辑，简化布局引擎，保证多环境布局一致性与 Dirty 更新性能。
> 专业自由画布、拖拽编辑器等自由定位场景属于后续扩展能力，不在首版范围内。

### 4.2 Stack 布局容器

`Stack` 是普通文档流容器，不脱离父盒空间，实现成本远低于绝对定位。

**尺寸策略：语法分层隔离（决策）**——子节点在声明期显式分为两层，**零额外遍历、无隐式运行时阶段**：

- **Content（基底层）**：参与 Stack 尺寸推导，尺寸 = Content 子节点内容包围盒（union）；显式尺寸（`layout` 指定 width/height）优先。
- **FillOverlay（浮层）**：不参与尺寸推导，仅按对齐规则（top-left / top-right / center / bottom-right 等）与边角偏移在已确定的 Stack 盒内摆放，天然解决 Fill 子节点的环形依赖。
- 子节点按**树序**绘制，树序靠后者自动在上层，实现局部堆叠（卡片角标、内部悬浮）。

```rust
Stack(
    content = [
        Rect(layout.fill(), visual.card()),                  // 基底层：参与尺寸
    ],
    fill_overlay = [
        Badge(layout.align_top_right().offset(8, 8)),        // 浮层：不参与尺寸，树序靠后在上
    ],
)
```

**边界场景兜底规则**：

- `FillOverlay` **仅在 Stack 内部生效**，放到其他布局容器（Flex/ScrollView）触发构建错误。
- `MinMax(Fill)` 允许用于 `FillOverlay`，约束基于 Stack 最终盒子生效。
- `FillOverlay` 支持多层叠加，按声明顺序决定绘制层级（树序靠后在上，贴合 z 序规则）。
- 多层嵌套 Stack：内层 Stack 的 Content/FillOverlay **完全隔离**，互不干扰尺寸计算。
- Content 为空或全 Fill 且无显式尺寸：构建期报错（不落到布局期 `UiLayoutError`）。

### 4.3 未来扩展（v1.1 后按需，首版不实现）

- `Grid` 栅格容器（行列轨道、跨行跨列）：首版砍掉，后台复杂表单栅格等场景后续按需补充。
- 变高虚拟列表：首版仅定高；变高 item 需要 item 高度缓存与估计占位，后续扩展。
- 若编辑器类场景大量需要自由定位，二选一，不恢复传统 CSS 式绝对定位：
  1. `FreeCanvas` 自由画布容器：容器内部子元素支持坐标定位，仅作用域隔离在容器内，不污染全局布局；
  2. 恢复局部绝对定位，但强制绑定 Stack/FreeCanvas 定位上下文，禁止全局脱离流。

### 4.4 Teleport 逻辑容器（portal，决策）

MVP 阶段下拉、Tooltip、编辑器悬浮面板、鼠标跟随浮层的**轻量过渡方案**：不改动布局引擎、不引入 position/z-index，远期平滑对接 FreeCanvas（4.3），无大规模重构债务。

- **原理**：源节点（source 锚点）正常留在原文档流布局；**portal 子树不参与父布局**，帧生成阶段统一提升至 ModalHost 顶层队列渲染，天然全局置顶。
- **坐标**：锚点/鼠标偏移仅存在于 `visual` 维度（`VisualConcern`），是**纯视觉偏移**，不污染布局层几何计算。
- **约束**：
  - 属逻辑容器，**无自身盒尺寸**（构建器不暴露 layout/visual 几何）；
  - **禁止嵌套 Teleport**；
  - 仅能绑定自身内部 source 锚点，维持组件封装。
- **视图状态**：portal 内部滚动/焦点/光标/选中直接复用 `ViewStateStore`（跨帧保持，见 [004-更新策略与状态保持](004-更新策略与状态保持.md)）；Teleport 销毁/模态关闭时遵循延迟回收逻辑。
- **点击外部关闭**：基座命中 portal 外部区域时仅抛 `UiAction::TeleportClickOutside(teleport_node_id)`，关闭逻辑由宿主业务实现；上层 Dropdown/Tooltip 组件套件封装通用"点击外部关闭"（见 [008-交互焦点与宿主接口](008-交互焦点与宿主接口.md)）。
- **鼠标跟随刷新**：仅修改 portal 视觉偏移字段时，只标记该 Teleport 子树为**视觉脏**——只重生成该子树绘制命令与命中区域，不重布局；仅当 portal 内部结构/尺寸变更时才触发完整布局重算（见 [004-更新策略与状态保持](004-更新策略与状态保持.md) 2）。
- **焦点遍历**：Teleport 子节点的焦点遍历链跟随目标渲染位置（ModalHost），脱离原始逻辑树；semantics 保留原始位置（见 [008-交互焦点与宿主接口](008-交互焦点与宿主接口.md) 2.10）。

### 4.5 局部 DrawOrder（决策）

补充 `VisualConcern.draw_order`：仅控制**当前直接父布局容器内**的绘制与命中顺序，作用域隔离，不产生全局 z-index，不破坏「树序决定层级」核心架构。与 Teleport、ModalHost 三层能力互补：

- `draw_order`：容器内局部分层，不脱离父盒；
- Teleport：跨父盒全局悬浮；
- ModalHost：全局模态弹窗顶层栈。

**类型设计**：

```rust
enum DrawOrder {
    InnerBottom(i16),  // 底层绘制组，默认权重 0
    Normal(i16),       // 普通内容层，默认权重 0
    InnerTop(i16),     // 顶层装饰组，默认权重 0
}
```

- 业务不传数字时等价 `InnerBottom(0)`/`Normal(0)`/`InnerTop(0)`，覆盖 95% 常规页面与游戏 HUD 场景（零使用成本）；
- 仅**同父容器、同分组内**权重参与排序；跨分组固定顺序 `InnerBottom` → `Normal` → `InnerTop`；
- 权重仅局部生效，不跨 Scope、不跨容器，无全局层级污染。

**渲染排序规则**（同一直接父容器下所有子节点统一排序生成绘制/命中序列）：

1. 先按分组优先级排序：InnerBottom 组全部在前，Normal 中间，InnerTop 最后；
2. 同分组内按权重升序绘制（数字越大越晚渲染、层级越靠上）；
3. 同分组、同权重节点保留原始树序，维持既有行为兼容。

**约束边界**：

1. 仅作用于**直接父布局容器**（Flex/Stack），嵌套多层 Scope 互不干扰；
2. 逻辑容器（FocusScope、IdentityScope、Teleport）自身无绘制盒，draw_order 对其无效，仅作用于内部绘制原语/布局子节点；
3. Stack 的 Content/FillOverlay **统一遵循同一套 draw_order 排序规则**（尺寸推导的语法分层隔离不变；绘制/命中排序不再硬编码"Content 必在下、FillOverlay 必在上"，默认树序兜底保持现有行为，可显式覆盖）；
4. 禁止依靠权重实现跨容器层级覆盖，复杂跨盒悬浮统一走 Teleport；
5. **DrawOrder 完全不改动焦点遍历**：绘制层级 ≠ Tab 导航顺序，Tab 顺序用 `tab_index` 独立调整（见 [008-交互焦点与宿主接口](008-交互焦点与宿主接口.md) 2.10）。

**编辑器差异化（无需底层删减）**：

- 基座完整保留带权重的 DrawOrder，全环境统一，不单独裁剪底层；
- 上层二选一实现定制约束：
  - 方案 A：封装自定义 `EditorLayer` 逻辑容器，业务完全不用 draw_order，上层提前按业务图层 z 值排好节点顺序，基座仅用默认 Normal；
  - 方案 B：编辑器宿主增加构建期校验，拦截带自定义权重的 DrawOrder，强制仅使用无参三档枚举；
- 编辑器渲染层可自定义 FrameSink 后置重排 DrawCommand，实现海量图层自由分层，上层接管复杂渲染逻辑。

**收益**：消除同容器内为调层级而大量嵌套 Stack 的 Hack；避免简单角标/内部浮层滥用 Teleport（省每帧额外布局/渲染/命中开销）；组件可实现完全自包含的局部装饰/浮层，恢复封装隔离；不引入全局 z-index、不改布局引擎纯函数逻辑。

## 5. 溢出与滚动

- 溢出控制：`visible` / `hidden` / `scroll`。
- 滚动偏移（`ScrollState { offset_x, offset_y }`）是**运行时交互状态，不是布局输出**：布局只计算滚动容器视口尺寸与内容尺寸；坐标变换与裁剪由 `resolve` 阶段完成，offset 由调用方作为**外部只读输入**（`scroll_inputs`）传入，`resolve` 不持久保存（见 [003-场景树与节点模型](003-场景树与节点模型.md) 6）。
- 跨帧记忆滚动位置由 M4 的 `ViewStateStore` 承担：宿主从仓库取 offset 组装成 `scroll_inputs` 传给 `resolve`——仓库只管存，`resolve` 只管读输入（等价理解：M2 实现"滚动渲染能力"，M4 实现"记住上次滚动到哪"）。
- 滚动容器尺寸 = 视口尺寸；内容尺寸由子节点布局得出。
- 命中测试在裁剪后仅对可视区域生效；滚动影响命中坐标换算。
- 裁剪区域在遍历/命令生成阶段合并进每条命令与命中区域（预合并 clip rect，见 [007-绘制与渲染后端](007-绘制与渲染后端.md) 2）。

## 6. 虚拟列表

长列表高性能渲染：仅渲染可视区域内容，`仅渲染可视区域`是布局层能力（`clip` + 流内槽位偏移），而不是把整列 item 全部放入布局计算。虚拟列表 item 由引擎按累计偏移在容器内容盒内排布，属流内能力，与定位无关。

`VirtualListView`（状态存于视图状态仓库）：

```
保存状态：item 数量、第一可见项、滚动偏移、定高 item 高度、间距、overscan 数量
接口：render_range(view) -> Vec<UiNode>  仅构建可视范围内节点
```

- **首版仅支持定高 item**：用首项索引 + 固定高度直接算出可视范围，无需 item 高度缓存。
- 变高 item：**暂不支持**，属后续扩展（见 4.3）。
- **item 身份**：虚拟列表 item **必须显式传入 `semantic-id`**，基座对虚拟化容器**不提供任何默认身份语义**（`auto-path`/`auto-stable-identity` 不适用）。离屏 item 不在树中，auto 身份随滚动释放/重建，跨滚动状态必然丢失。
- **数据与职责边界**：业务手动管理全量数据（数据在宿主/业务侧，业务所有），虚拟列表**只负责可视区渲染与滚动定位**，不承担身份分配与 item 状态保持。需要跨滚动保持的 item 状态（选中/展开等）放在业务数据中，不依赖视图状态仓库。
- 与局部 Dirty 更新协同：单 item 变更只重算该 item 槽位，不重算整列。

## 7. 布局规则

- ✅ 布局引擎为纯函数：相同节点 + 约束 → 相同盒子。
- ✅ 布局只消费 `layout` 维度，不读取 `visual`/`interact`/`identity`。
- ✅ 首版无相对/绝对定位，层级堆叠仅靠树序 + Stack + 页面/模态栈（见 4.1）。
- ✅ 不新增 z-index 数值维度，绘制顺序即层级（见 [007-绘制与渲染后端](007-绘制与渲染后端.md)）。
- ✅ 裁剪以命令级预合并 clip rect 表达，遍历阶段合并进命令与命中区域（见 [007-绘制与渲染后端](007-绘制与渲染后端.md) 2）。
- ✅ Stack 为普通文档流容器，子节点分 Content/FillOverlay 两层（语法分层隔离）：尺寸只由 Content 推导，FillOverlay 对齐摆放不参与尺寸；FillOverlay 多层叠加按树序定层级。
- 🔧 `FillOverlay` 仅在 Stack 内部生效，其他容器使用触发构建错误；非法尺寸搭配构建期报错。
- ✅ 统一 Flex + wrap 开关：`wrap=false` 单行全局 Fill；`wrap=true` 自动换行、Fill 仅单行内部、跨行不共享空白（见 2.1）。
- 🔧 盒子尺寸必须满足最小约束，无法满足时返回 `UiLayoutError`，不 panic。
- ✅ MinMax 为修饰包装器（`Raw`/`Constrained` 二选一）；构建期拦截 Fixed 包裹、min>max、嵌套约束（见 3.2）。
- 🔧 虚拟列表不得把整列 item 放入布局计算，只构建可视范围节点。
- ✅ 虚拟列表 item 必须显式 `semantic-id`，缺失即 `UiBuildError`；基座不提供虚拟化默认身份。
- 🔧 虚拟列表只负责可视区渲染与滚动定位，业务手动管理全量数据。
- ✅ 虚拟列表首版仅支持定高 item；变高暂不支持（见 4.3）。
- 🔧 滚动偏移属于视图状态；定高 item 高度为容器配置，无需高度缓存，不进 `UiNode`。
