# 006-布局引擎

## 1. 目标与边界

Tela 是客户端 UI 基座，不复刻 CSS Flexbox。布局优先保证约束传播、结果确定性和可审计的测量次数；复杂但低频的 Web 弹性糖以显式节点组合替代。

当前布局核心不变量是：**一次根级 `LayoutEngine::measure` 中，每个源 `UiNode` 最多进入一次测量器。** 容器可以先收集自然项目、再计算剩余空间、再调度分配项，但不会用临时约束测一遍后再回头重测同一子树。

这条不变量只覆盖一次 resolve 内的物理测量。下一帧的新树、约束变化或 Dirty 缓存失效仍会重新测量；缓存命中则直接复用已经确定的 `LayoutBox`。

| 能力 | 当前契约 |
|---|---|
| 线性排列 | `Row`、`Column`、`BaselineRow` |
| 自然换行 | `Wrap`（水平、无剩余空间分配） |
| 显式剩余空间 | `Expanded`、`Spacer` |
| 单子盒 | `Frame` |
| 同盒堆叠 | `Stack`、`Overlay(OverlaySpec)` |
| 内容 | 固定、百分比、自动、`MinMax`、padding、margin、border、clip、overflow |
| 长内容 | `ScrollView`、定高 `VirtualListView` |
| 不支持 | `flex-shrink`、主轴 `SpaceBetween/SpaceAround`、交叉轴 Stretch、泛化 `align-self`、Grid、相对/绝对定位 |

## 2. 契约模型

布局算法由 `NodeKind` 表达，通用盒模型保留在 `LayoutConcern`：

```text
UiNode {
  kind: Row | Column | Wrap | Frame | Expanded | Spacer | BaselineRow
      | Stack | Overlay(spec) | ScrollView | VirtualListView(spec) | Primitive,
  layout: { width, height, margin, padding, border_width, gap,
            cross_align, clip, overflow },
  ...
}

Constraints { min_w, max_w, min_h, max_h }
LayoutBox   { x, y, w, h, first_baseline, children }
```

`LayoutConcern` 不再承载方向、换行、主轴分布或 Stack 分层开关。它们若继续是布尔或枚举字段，就会重新形成互斥字段组合，并迫使引擎猜测一棵树到底要使用哪一种算法。

布局读取 `NodeKind`、`layout` 和文本叶子的 `content` 度量；它不读取 `visual`、`interact` 或 `identity`。`visual.draw_order` 只影响 resolve 之后的局部绘制/命中序，不改变布局尺寸。

## 3. 原语与调度

### 3.1 Row 与 Column

`Row` 水平排列，`Column` 垂直排列。二者都支持 `gap`、margin、padding、border 和交叉轴 `CrossAlign::{Start, Center, End}`。`cross_align` 只允许出现在 `Row`/`Column`；其他布局节点使用非默认值会在构建期返回 `UiBuildError::InvalidLayoutShape`，避免字段被静默忽略。

调度顺序如下：

1. 计算容器已声明的主轴和交叉轴尺寸，以及最终可用内容区；
2. 每个自然子项只接受一次最终的子约束并完成测量；
3. 若主轴已解析为有限尺寸，计算 `内容区 - 自然项目 - gap - margin`；
4. 将剩余空间均分给直接子项中的 `Expanded` 和 `Spacer`，然后各测一次；
5. 以所有已确定的盒生成容器盒和坐标。

```rust
let toolbar = LayoutContainer::row([
    title,
    LayoutContainer::spacer(),
    search,
    LayoutContainer::spacer(),
    actions,
])
.layout(LayoutConcern {
    width: Some(Size::fixed(viewport_width)),
    cross_align: CrossAlign::Center,
    ..LayoutConcern::default()
});
```

`Spacer` 没有子节点，只消费一份剩余空间。`Expanded(child)` 自身拥有分到的主轴区域，内部 child 在这一最终区域的上限内只测一次；如果 child 也需要填满该区域，可显式写 `Size::percent(1.0)`。这使“区域占满”和“内容拉伸”成为两个独立意图。

若主轴没有有限的已解析尺寸（例如 `Auto` 容器），不存在可定义的“剩余空间”：`Spacer` 退化为零尺寸，`Expanded` 按内部 child 的自然尺寸排列。`Expanded` 和 `Spacer` 只能是 `Row`/`Column` 的直接子项，出现在 `Wrap` 会报 `AllocationInWrap`，出现在其他父节点会报 `InvalidLayoutShape`。

### 3.2 Wrap

`Wrap` 是自然宽度的水平换行容器。项目按自然尺寸顺序放入当前行，超出容器内容宽度时开始新行；支持 `gap`、margin、padding 和显式宽高，但不支持 `Expanded` 或 `Spacer`。

这不是功能遗漏，而是刻意消除“先知道每行内容才能分配 Fill、又必须先分配才能知道行内容”的回溯依赖。标签、文件 chip 和静态图块应保持自然/固定尺寸；需要完整主轴弹性时使用 `Row`/`Column`，不要把两种算法混在一个节点中。

### 3.3 Frame

`Frame(child)` 是单子节点盒。它负责显式宽高、padding、border 和 clip 边界，child 在最终内容区约束下测量一次。Frame 自己的固定尺寸不会隐式 Stretch child；要让 child 填满某个轴，child 显式声明 `Size::percent(1.0)`。

`Frame` 用于替代旧交叉轴 Stretch 的隐式效果，例如固定表格行高、固定预览区域和有边界的输入框。这样行高/列宽属于树中的实际盒，不是父容器在第二轮测量里改写出来的结果。

### 3.4 BaselineRow

`BaselineRow` 是专门的水平文字基线容器，不是 `CrossAlign` 的一个分支。文本叶子通过 `TextMeasurer` 提供 `first_baseline`；容器以最大上行高度为目标移动各子项。没有文字基线的项目按交叉轴末端参与对齐，因此图元也有确定结果。

文字和文字需要排版基线时使用 `BaselineRow`。图标字体的可见墨迹中心通常不等于文字基线，图标加标签应使用 `tela-ui::Text::prefix`/`suffix` 生成 `CrossAlign::Center` 的普通 `Row`，并由 `tela-icon` 的 `VisualConcern::visual_offset` 做仅绘制层的光学校正。

## 4. Stack 与 Overlay

`Stack` 的普通子项在同一原点测量，其 union 决定未声明尺寸时的 Stack 尺寸。`Overlay(spec)` 是 Stack 的专用单子节点包装器：普通内容尺寸确定后，Stack 才以最终内容区约束测量 Overlay 一次，再按 `OverlaySpec` 的锚点、偏移和 `fill_width`/`fill_height` 摆放它。

```rust
let card = LayoutContainer::stack([
    content,
    LayoutContainer::overlay(
        badge,
        OverlaySpec {
            align: StackAlign::TopRight,
            offset: PixelOffset { x: -4.0, y: 4.0 },
            ..OverlaySpec::default()
        },
    ),
]);
```

Overlay 不参与 Stack 的尺寸推导，因此不会把角标、弹层或背景图片撑大内容盒。它只能是 Stack 的直接子项；Stack 必须至少有一个非 Overlay 子项。违反任一条件在 `UiTree::new` 阶段返回结构化错误。

位置和绘制层级是两个独立意图：`OverlaySpec` 只控制几何摆放，`VisualConcern::draw_order` 挂在 Overlay 包装器本身时控制它相对于 Stack 直接兄弟的绘制/命中顺序。图片背景使用 `DrawOrder::InnerBottom`，角标或弹层可用树序或 `InnerTop` 明确置顶。

Stack/Overlay 不是自由绝对定位。没有 `z-index`、相对坐标上下文或跨祖先锚点；这类能力仍属于将来的 `FreeCanvas`/锚点定位设计。

## 5. 尺寸与盒模型

`Size` 只有三个基础来源：

| 形式 | 含义 |
|---|---|
| `Size::fixed(px)` | 显式逻辑像素 |
| `Size::percent(ratio)` | 相对父约束的可用最大尺寸 |
| `Size::auto()` 或未声明 | 叶子按内容、容器按已确定子盒推导 |

`Size::constrained(min, max)` 是以 Auto 为基准的 `MinMax` 包装。解析顺序是：基础值 -> 节点 MinMax -> 父 `Constraints`。`MinMax` 不能包裹 `Fixed`，`min > max` 也不合法。

旧的 `Size::fill()`/`BaseSize::Fill` 已删除。沿主轴吃剩余空间必须使用 `Expanded`/`Spacer`；在某个已经确定的 Frame 或 Expanded 区域内填满则使用 `Size::percent(1.0)`。这把“谁分配空间”和“谁在已分配区域内拉伸”拆开，避免隐式回流。

margin 属于子项并参与同级占用；padding 和 `border_width` 从父内容区扣除。`clip` 或 `Overflow::{Hidden, Scroll}` 最终被 resolve 投影为每条绘制命令的祖先 clip 交集，renderer 不维护可变裁剪栈。

## 6. 滚动与虚拟列表

`ScrollView` 纵向摆放自然子项，viewport 尺寸由自身布局决定，滚动偏移不写进树而由 `scroll_inputs: HashMap<SemanticKey, ScrollState>` 在 resolve 时注入。`VirtualListView` 目前只支持定高 item：完整内容高度由 `total_items`、`item_height` 和 `item_spacing` 推导，已构建窗口中的每项必须持有业务稳定 `semantic-id`。

滚动/虚拟化不改变上面的单次测量规则。可见子树每次 resolve 只在最终约束下测量一次；在 Dirty 模式下，同 key、同约束且指纹未变的子树可以整盒复用。

## 7. 已移除功能与替代

| 旧能力 | v2 写法 | 现有迁移 |
|---|---|---|
| `FlexDirection::{Row, Column}` | `LayoutContainer::{row, column}` | demo shell、form、table、widgets 已迁移 |
| `wrap: true` | `LayoutContainer::wrap` | 自然标签/流式场景；禁止分配项 |
| 主轴 `SpaceBetween`/`SpaceAround` | 在意图位置插入一个或多个 `Spacer` | Toolbar、Button、Select、Table 单元格 |
| `Fill` | 主轴用 `Expanded`/`Spacer`；已分配区域内用 `percent(1.0)` | Button 居中、工具栏尾部、固定行盒 |
| 交叉轴 `Stretch` | `Frame`/显式行高列宽/百分比 child | Table 头与虚拟行 |
| `CrossAlign::Baseline` | `BaselineRow` | 文字-文字行；图标文字仍为普通居中 Row |
| `StackLayer::FillOverlay` | `Overlay(OverlaySpec)` | ImageBackground、Select/Cascader、抽屉、modal |
| `flex-shrink` | 滚动、裁剪或业务明确的固定尺寸 | 当前 demo 与组件无依赖 |

因此，已使用的布局能力都有等价或更明确的表达。v2 不承诺 CSS 兼容：权重化 grow、自动 shrink、多行内部 Fill、泛化 `align-self` 和栅格布局没有伪装成“以后再算”的字段，调用方必须选择明确的容器结构。

## 8. 缓存、验证与验收

`DefaultLayoutEngine` 在测试中记录每个源节点的访问次数；覆盖含 `Expanded` 和 `Overlay` 的树，断言最大次数为一。Dirty 路径通过同一 `ChildMeasurer` 调度接口获取子节点：先检查 key/约束/指纹缓存，未命中才以最终约束测量，不能先递归预测再让父容器重测。

构建期至少校验：

- `Frame`、`Expanded`、`Overlay` 恰好一个 child，`Spacer` 没有 child；
- `Expanded`/`Spacer` 只能直接位于 `Row`/`Column`，`Wrap` 禁止二者；
- Overlay 只能直接位于 Stack，Stack 不能只有 Overlay；
- `cross_align` 的非默认值只能用于 `Row`/`Column`；
- Percent、MinMax 与虚拟列表窗口范围合法。

当前自动化验收覆盖：Row/Column/Wrap 几何、Explicit Spacer/Expanded 分配、Frame 固定行盒、BaselineRow、Stack/Overlay 尺寸隔离与绘制顺序、滚动 clip、VirtualList、Dirty 缓存、Raster 集成，以及每源节点单次测量。不需要浏览器来验证这一层的纯布局契约。
