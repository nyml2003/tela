# CC 远程会话产品意图

> 状态：M0 实施中。协议 crate（`services/cc-protocol`）与 guest-runtime 桥 fuel 修补已落地；
> 中继、桌面 agent、手机 app 与 Android 宿主接线并行实施中，本文的"实施中"章节以源码为准
>
> 拓扑：手机 APP（tela/Android）+ 2 核 2G 云服务器（中继）+ WSL2 桌面（agent + claude CLI）
>
> 框架事件、组件状态和帧提交规则以
> [036-事件系统与组件生命周期机制](036-事件系统与组件生命周期机制梳理.md) 为准；
> 桥 `net.http.request` 契约与回投生命周期见 [039](039-桥net能力与移动回投实施目标.md)

## 1. 产品定义

CC Remote 让用户离开台式电脑时，仍然可以在手机上与家里运行的 Claude Code 会话交互：发消息、
看流式输出、批准或拒绝工具权限请求、管理多个会话。台式电脑负责真正的模型调用与代码执行，手机
只做显示与决策，云服务器只做转发与缓冲。

```
手机 APP（tela/Android） ⇄ HTTP 短轮询(1.5s) ⇄ 中继（Rust, 2c2G） ⇄ 自定义 TCP 帧 ⇄ 桌面 agent（Rust）
   guest WASM 经桥 net.http.request 出站        std 线程+阻塞 IO                子进程驱动 claude CLI
                                               （agent 主动外连，家里不开端口）    （stream-json 协议）
```

它首先是一个**自持的个人工具**：中继、事件日志与凭据都在用户自己的服务器上，不经第三方推送
服务，也不依赖云沙箱。同类的开源形态（Happy 等）验证过产品可行性；本产品不复用它们，而是
作为 tela 基座的第一个真实联网 C 端产品，把"手机端联网 guest"这条链路在自家框架里走通。

## 2. 首版边界

- 单用户：一个 token 同时鉴权手机与桌面 agent；不做多用户、多桌面。
- Android 先行：复用 `ops build android` 真机链路；iOS 走既有静态产品路径后续跟进。
- 无推送通知（FCM/APNs 后置）：app 前台轮询实时收，后台由中继缓冲、回来补拉。
- 无端到端加密：中继可见明文（TLS 由前置层承担）；E2E 加密后置（见 §7）。
- 会话即 Claude Code 会话：工作目录在 agent 侧白名单内选定，手机不做文件浏览或编辑器。

## 3. 决策记录

| 决策 | 结论 | 理由 |
|---|---|---|
| 桌面 agent 语言 | Rust（`tela-cc-agent`），不用 Node/Agent SDK | 全链路单语言单二进制；stream-json 与权限控制协议经本仓库实测已可自己实现（§5）；符合仓库手搓文化 |
| 中继技术栈 | std::thread + 阻塞 IO，无 tokio/axum | 2 核 2G 服务器资源紧张；个人规模（≈1 手机 + 1 agent 连接）不需要异步 runtime；第三方依赖仅 httparse 与 serde 家族 |
| 传输协议 | phone↔relay = HTTP/1.1 REST；agent↔relay = 长度前缀 JSON 帧 | 手机链路保留标准 HTTP 便于 curl 调试与公开暴露；agent 链路两端自家代码，自定义帧最省依赖 |
| 手机联网路线 | 桥**具名能力** `net.http.request` + ~1.5s 轮询 | 不进 std（五端同时实现约束）；`BridgeEvent::Message` 推送是 [桥/000](桥/000-宿主桥总览.md) §10.2 明确后置的 breaking change，v1 不碰；轮询基建将来被推送路径复用 |
| 仓库布局 | `apps/cc-remote` + `products/cc-guest` + `services/{cc-protocol,cc-relay,cc-agent}` | monorepo 单一事实源；协议 crate 仿 `speed-gear-protocol` 范式三端共享 |

## 4. 协议摘要

唯一权威是 `services/cc-protocol/`（类型 + `fixtures/*.json` canonical 样例 + roundtrip
测试）。此处只摘要语义，字段以 crate 为准：

- **seq 游标**：事件由中继 `append` 时统一赋 `seq`（每用户全局单调、无空洞）；手机只追游标
  （`GET /v1/sync?since=<seq>`），不猜顺序。中继无持久化重启导致 seq 归零时，手机收到
  `cursor_reset` 后从 0 重拉。
- **权限三方竞态仲裁**：手机先到者胜（`Pending → Resolved` 单向状态机，后到 409）；agent
  120s 本地超时自行拒绝并上报 `agent-timeout`（中继仍 Pending 则采纳，已 Resolved 则丢弃）；
  中继清扫线程兜底 `relay-expired`。agent 侧挂起只 resolve 一次。
- **REST 面**（Bearer 鉴权）：`/v1/health`（免鉴权）、`POST /v1/sessions`、`GET /v1/sync`、
  `POST /v1/sessions/<id>/messages`、`POST /v1/permissions/<id>`。
- **agent 帧**：连接后 hello 握手（token + protocol_version）→ 30s 心跳；上行 `AgentEvent`
  （中继赋 seq/ts），下行 `create_session` / `run_turn` / `permission_decision` /
  `cancel_turn`。

## 5. CLI 线格式实测记录（claude 2.1.245，2026-08 本机探针）

以下全部为实测结论（样本来自 WSL2 内已登录的 `claude` CLI），agent 的解析器以本节为准：

- **启动参数**：`claude -p --input-format stream-json --output-format stream-json --verbose
  [--resume <session_id>] [--permission-prompt-tool stdio]`。
- **init**：`{"type":"system","subtype":"init",...,"session_id":"<uuid>",...}` —— `session_id`
  在顶层；`cwd`、`tools`、`permissionMode` 同在此消息。
- **assistant**：`message.content[]` 内容块，`type` 为 `text` / `thinking` / `tool_use`；
  `tool_use` 块含 `id`、`name`、`input`；`message.id` 为稳定消息 id；顶层 `session_id`。
- **user（tool_result）**：`message.content[]` 内 `type:"tool_result"` 块，含 `tool_use_id`、
  `content`、`is_error`；权限被拒时 `tool_result_meta[].non_execution_kind` 为
  `"user-rejected"`。
- **result**：回合结束消息，含 `subtype`（如 `success`）、`total_cost_usd`、`duration_ms`、
  `session_id`、`result`（最终文本）、`permission_denials`。
- **噪音**：`{"type":"system","subtype":"thinking_tokens",...}` 增量消息需要过滤。
- **多回合注入**：`result` 之后**同一进程**继续向 stdin 写下一条 user 消息即可开启下一回合；
  `session_id` 不变，新回合开始时重发一条 init。→ 每会话一个长驻子进程，`--resume` 仅用于
  进程崩溃后的恢复路径。
- **输入形状**：`{"type":"user","message":{"role":"user","content":[{"type":"text","text":...}]}}`。
- **权限询问的启用**：`--permission-prompt-tool stdio`（该 flag 不在 `--help` 里，属隐藏
  flag；二进制内字符串证实，实测被接受）。不加此 flag 时，无头模式对权限需求**自动拒绝**：
  先出 `{"type":"system","subtype":"permission_denied","tool_name":...,"tool_use_id":...,
  "message":...}`，随后是 `is_error:true` 的 tool_result。
- **权限请求形状**（stdout 上的一条独立消息）：

  ```json
  {"type":"control_request","request_id":"<uuid>","request":{
    "subtype":"can_use_tool","tool_name":"Bash","display_name":"Bash",
    "input":{"command":"...","description":"..."},"description":"...",
    "permission_suggestions":[...],"blocked_path":"...","tool_use_id":"call_..."}}
  ```

- **应答包络**（写回 stdin；对官方 SDK `@anthropic-ai/claude-agent-sdk` 源码核对一致，且实测
  打通完整批准回路）：

  ```json
  {"type":"control_response","response":{"subtype":"success","request_id":"<同 request_id>",
    "response":{"behavior":"allow","toolUseID":"call_..."}}}
  ```

  拒绝时 `behavior` 为 `"deny"`。注意 `request_id` 嵌在 `response` 对象内，不是顶层。
- **stdin 关闭的后果**：CLI 尝试经 stdio 询问但无应答方（stdin 已 EOF）时，权限请求以
  `AbortError: Stream closed` 失败并按拒绝处理——agent 必须在整个会话生命周期保持 stdin 打开。
- **自动放行**：`echo` 一类只读命令在默认模式下不触发询问直接执行；带写入重定向等"有风险"
  命令才产生 `can_use_tool`。这正是产品期望的交互密度。

## 6. 部署与运维

- **中继**：单二进制（release + strip），systemd 常驻；2c2G 上可加 `MemoryMax=64M` /
  `CPUQuota` 兜底。线程有界（2 accept + 每手机连接一线程 + agent 读写 + 清扫），全部阻塞
  IO，空闲 CPU ≈0。事件日志内存环形（10k 条）+ 可选 JSONL 追加。
- **TLS**：首选 Tailscale——手机与桌面 agent 入 tailnet，中继前 `tailscale serve` 自动
  Let's Encrypt；agent 链路走 tailnet 内 TCP，天然加密。**公网明文 agent 链路禁用**（token
  与会话内容不可裸奔）；无 Tailscale 的公网场景需另行评估 TLS 前置（stunnel/Caddy），M2 前不
  支持。开发态用 `adb reverse tcp:8787 tcp:8787` 直连本机中继，manifest 已允许 cleartext。
- **桌面 agent 常驻（WSL2）**：systemd **user** 单元 + `Restart=always`；Windows 侧计划任务
  在登录时 `wsl.exe -d <distro> -u <user> --exec systemctl --user start cc-agent`；
  `.wslconfig` 设 `vmIdleTimeout=-1` 防空闲停机；agent 自身指数退避重连，掉线经
  `agent_status` 事件让手机可见。
- **凭据**：中继 token 经 env（`CC_RELAY_TOKEN` 等）注入，不进 CLI 历史与仓库。

## 7. 安全边界

- 中继 token 只存**宿主侧**（Android `RelayConfig` 经 BuildConfig 注入），永不进入 guest
  WASM；guest 只见相对 path。
- 中继可见明文（含会话内容）；威胁模型是"自己的服务器自己信"。E2E 加密（手机/agent 端到
  端、中继零知识）后置，协议 envelope 已预留扩展位。
- agent 侧工作目录白名单（`CC_AGENT_CWDS`）：`run_turn` 校验 cwd，拒绝白名单外目录。
- 权限默认拒绝：120s 无响应即拒，宁可多问一次也不静默放行。

## 9. 明确不做的事（首版）

- 推送通知（FCM/APNs）、多用户、多桌面、E2E 加密、iOS 端。
- 手机端文件浏览器/编辑器；会话内图片与附件。
- 中继侧业务逻辑（除权限状态机与缓冲外，中继不理解会话内容）。
- 绕过 Claude Code 权限模型的"全自动"模式；`--dangerously-skip-permissions` 不进入产品。
