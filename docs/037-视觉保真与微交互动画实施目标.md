## 1. 问题

核心症状：界面观感远差于现代 web，"纯色块 + 1px 边框 + 换色 hover"的上世纪扁平感。

根因（全部经源码核验，非文档推断）：

| # | 根因 | 证据 |
|---|---|---|
| 1 | 唯一生产渲染器 wgpu 只实现 4/12 原语，渐变/阴影/圆/多边形/九宫格静默丢弃 | `crates/presentation/renderers/wgpu/src/renderer.rs:142-157`（能力位全 false），未支持 payload 落入 `unsupported_commands` |
| 2 | 全仓库零模糊、零动画：无 tween/easing/animation 任何实现；hover/press 为二值换色 | 全局检索仅命中 IME/滚动等无关代码 |
| 3 | 文字路径弱：内嵌 WQY 子集单一字体、逐段 CPU 光栅化整块纹理上传、无 glyph atlas、`subpixel: false` | `tela-fonts/src/lib.rs:15-18`、`wgpu/src/text.rs:23-70`、`renderer.rs:155` |
| 4 | 三层脱节：token 层定义 elevation/阴影（`ui/foundation/src/tokens.rs:130-154`）但无组件消费，渲染器也不支持 | apps 全目录 0 处 `Fill::Linear/Radial/Shadow` 使用 |
| 5 | docs/007 §6.1 虚标渐变已实现（"256 像素色带纹理"），代码实际 `linear_gradient: false` | 文档与代码不一致，需同步修正 |

## 2. 现状：架构能长出什么

### 2.1 已表达、已投影、只差 wgpu 实现（零架构变更）

| 视觉效果 | 契约 | Kernel 投影 | wgpu 现状 |
|---|---|---|---|
| 线性/径向渐变 | `Fill::Linear/Radial`（`contract/src/paint.rs:44-51`） | `core/src/resolve.rs:781-786` 已产出 | 丢弃 |
| 真阴影（blur_radius/inset） | `ShadowSpec`（`paint.rs:55-64`） | `resolve.rs:796-803` 包装任意本体 | 丢弃 |
| 圆/椭圆 | `contract/src/draw.rs:79-91` | `resolve.rs:746-761` | 丢弃 |
| 按压位移 | `visual_offset`（`contract/src/node.rs:475`） | 已生效 | 已支持 |

结论：web 级静态视觉的大头只欠渲染器实现，Kernel/契约主干零改动。

### 2.2 契约缺口（加法修订）

- 渐变+圆角组合退化：`resolve.rs:770` 仅 `Fill::Solid + radius` 走 `RoundedRect`，其 `fill: Option<Color>` 装不下渐变；
- 图片圆角：`DrawPayload::Image` 无 radius 字段；
- 透明度：`VisualConcern` 无 opacity 槽位，绘制端无 opacity 组语义。

### 2.3 动画：Kernel 无状态约束下的合法路径

Kernel 必须保持纯函数（不读时钟/随机数），时钟不属于 Kernel。业界三种模型对齐：

| 模型 | 时钟/插值归属 | 进 tela 的结论 |
|---|---|---|
| CSS transition | 声明在样式，插值在宿主合成器 | 插值放宿主 = 五端各写一遍，不一致，否 |
| Flutter Ticker | 时钟 = 宿主 vsync；插值状态在 widget State；每 tick 重发树 | 完全匹配：树重发便宜（布局缓存），状态在组件 owner |
| SwiftUI .animation | render 层有状态 diff | Kernel/resolve 需持状态，违反无状态约束，否 |

**定案：Flutter 骨架 + CSS 表皮**——作者侧是 CSS 式隐式 transition（只声明 duration/easing），
运行时是宿主哑计时器 + guest 内单一插值实现。

五端一致性的论证（这是本方案的成立前提）：

1. 插值逻辑只有一份：easing/retarget/新旧视觉值比较全部在 ui 层（进 guest，WASM/native 同源）；
2. 时间戳由宿主随 Tick 携带，guest 全程不读钟——插值是 `(from, to, start, now, easing)` 纯函数，
   相同时间戳序列 = 相同帧，可做确定性 golden 测试；
3. 只插值视觉槽位（fill/border_color/border_radius/shadow/visual_offset/opacity，全部在
   `VisualConcern`，`node.rs:461-476`，不影响布局盒）→ 命中区域停在逻辑终点值，036 的
   已呈现帧命中红线天然成立；布局缓存指纹不变，每 tick 的 re-resolve 走缓存直达；
4. 帧率差异只影响平滑度不影响结果（与 CSS 跨刷新率行为一致）。

### 2.4 现有可复用基建

## 3. 设计原则

1. **Kernel 无状态**：时钟、插值状态一律在宿主/app/组件 owner，Kernel 不新增任何读时域能力；
2. **五端一致优先于单端炫技**：任何插值/降级逻辑必须单点实现于 guest 侧，宿主只做哑计时与 present；
3. **wgpu 是唯一视觉基准**：raster 降级教义收窄为真弱宿主兜底（no_std 路径保留），视觉验收与
   回归门全量走 wgpu 离屏回读；
4. **契约只做加法**：不改既有字段语义，bundle `format_version` 单调升级；
5. **不怕改动大，只怕不达标**：以 win32-editor + 文件管理器达到"现代 web 后台观感"为达标判据。

## 5. 明确不做（本阶段）

- enter/exit 弹层动画（节点存在性变化，需生命周期配合，二期）；
- 布局动画（尺寸/位置插值，每帧 relayout，架构风险高）；
- backdrop blur / 通用 blur pass；
- SwiftUI 式 render 层有状态 diff；
- raster 向 wgpu 看齐的视觉补课（已决策：raster 退出视觉基准角色）。

## 6. 风险与退路

| 风险 | 缓解 |
|---|---|
| opacity 合成语义（嵌套/裁剪下的叠加顺序） | P1 前置设计文档先行，wgpu 单 pass per-node opacity 起步，组语义后置 |
| vsync 定时器平台兼容性（老 Windows / RDP 会话） | 消息循环定时器退路保底，运行时探测选择 |
| 渐变+圆角契约改动波及 ABI wire（`app-abi/src/frame.rs` 镜像） | 只加不改：新变体/新 Option 字段，序列化向后兼容，`format_version` 升版硬校验 |
| lavapipe draw 在本机不可靠（render_test.rs:194 已记录） | golden 门以 write_texture 回读链路校验环境；必要时 CI 换宿主 GPU runner，浏览器 gpu_probe 为旁证 |
| 动画期间树重发放大成本 | 布局缓存指纹命中 + 只动视觉槽位（布局不跑）；AppStatus 停表防止空转 |

## 7. 执行规则

- 🔧 每个新原语必须同时交付：wgpu 实现、能力位诚实上报、离屏 golden 快照，缺一不合入；
- 🔧 动画插值实现只允许存在于 guest 侧单一 crate，宿主代码不得出现任何 easing/插值计算；
- 🔧 契约改动必须同步 `app-abi` wire 镜像与 bundle 版本校验；
- 👁 docs/007 在 P1 完成前不得再声称未实现的能力（失真即改）；
- ✅ Kernel（contract/core）保持无时钟、无随机、无宿主对象读取（现行约束延续）。

## 8. 落地后的开发契约与验收状态

### 8.1 字体不是全局配置

- `UiResources::fonts()` 返回产品装配后的 `FontDescriptor` 列表；当前受控目录包含 Noto Sans SC
  Regular、Noto Sans SC Medium 和 Material Symbols Rounded。
- 字体选择器只保存稳定 `TextStyleRef`，不接触字体字节。每个 `Text` 的 `font` 字段独立投影到
  `TextContent.font`，因此同一帧允许不同 Text 使用不同字体/字重。
- `ui!` 的 `<Text font={...}>` 是正式入口。未知 token 在目录查询时不伪装成已注册项；renderer
  只在真正解析未知 token 时按确定规则回退正文。

### 8.2 动画状态、时钟与帧调度

- 隐式 transition 的 controller 存在组件 owner 私有跨帧状态中；keyed 组件重排跟随业务身份，候选帧
  失败不会提交 controller 变更，组件移除后状态回收。嵌套 `ViewOutput` 必须把
  `AnimationSchedule` 向父树合并，任何中间层都不能吞掉调度请求。
- `AnimationController` 是显式底层 API；`TransitionExt` 和 `ui!` 的 `transition` 字段是声明式表面。
  retarget 必须从当前插值值起步，不能从旧起点或旧目标重启。
- `Tick` 始终同步 guest 的单调时钟，即使当前没有动画也不产生新帧。所有输入宿主必须先注入一次
  当前时钟，再派发可能改变 transition 目标的输入；否则长时间空闲后的第一帧会因旧时间原点直接
  跳到动画终点。
- 宿主只提供时间与唤醒：WebView 用 `requestAnimationFrame`，Win32 用 `DwmFlush` 对齐的活动期
  timer（16ms fallback），Android 用 NDK `AChoreographer_postFrameCallback64`，macOS/iOS 用
  `CADisplayLink`。宿主禁止出现 easing 或属性插值。`animation_active=false` 后必须停掉高频显示回调。

### 8.3 `ui!` 正式视觉字段

内建 `Frame`/布局容器、`Text`、`Image` 支持 `shadow`、`opacity`、`visual_offset`、`transition`；
`Text` 另支持逐节点 `font`。字段最终仍降低为 `VisualConcern` / `TextContent`，宏不创建 renderer
私有旁路。opacity 是单节点命令透明度，不是子树 group opacity；后者仍是明确未实现能力。
