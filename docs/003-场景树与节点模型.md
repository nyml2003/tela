# 003-场景树与节点模型

## 1. 树模型

UI 树是**值语义**的 `UiNode` 树，由宿主在每次刷新时从数据快照构建。基座不持有"正在变化的树"，而是把树当作推导布局、绘制命令与命中区域的输入。

### 1.1 维度槽位模型

`UiNode` 按**关注点维度**拆成独立槽位，取代平铺的巨型 `UiStyle`。每个槽位只含单一维度的字段，维度之间零重叠、零互读、零死字段：

```
UiNode
 ├─ kind       NodeKind       解释哪些维度、对后代产生什么影响
 ├─ layout     Option<LayoutConcern>    尺寸/边距/交叉轴对齐/裁剪/溢出
 ├─ visual     Option<VisualConcern>    填充/圆角/边框色/阴影/裁剪/九宫格/局部绘制序 draw_order
 ├─ interact   Option<InteractConcern>  可点/可悬停/可聚焦/输入/模态/业务绑定 BindId/焦点序 tab_index
 ├─ identity   Option<IdentityConcern>  key策略/更新模式/语义id（向下生效）
 ├─ content    Option<ContentConcern>   文本/纹理/几何
 └─ children   Vec<UiNode>
```

设计原则：树只描述"这帧该长什么样"。可变状态（焦点、光标、滚动、选中、弹窗开关）不放进树，放在独立视图状态仓库（见 004）。

### 1.2 槽位与消费者一一对应

| 槽位 | 消费者 | 文档 |
|---|---|---|
| `layout` | 布局引擎 | [006-布局引擎](006-布局引擎.md) |
| `visual` + `content` | 绘制层 | [007-绘制与渲染后端](007-绘制与渲染后端.md) |
| `interact` | 交互层 | [008-交互焦点与宿主接口](008-交互焦点与宿主接口.md)；`BindId` 业务绑定见 [012-业务数据绑定](012-业务数据绑定.md) |
| `identity` | 更新/diff 层 | [004](004-更新策略与状态保持.md)、[005](005-key身份策略.md) |

任何槽位被消费时不得读取其他槽位：布局不读 `visual`，绘制不读 `layout`，交互不读两者。

### 1.3 构建器约束

每个 kind 通过构建器 API 只暴露合法组合，用**类型形状**强制正交，不靠约定：

- 逻辑容器（`FocusScope::new(...)` 等）构造不出 `.layout(...)`、`.visual(...)`——零几何、透明。
- 布局容器必须带 children，只解释后代各自声明的 `layout`，不伸手改子节点 visual/interact。
- 原语（`Text::new(...)` 等）要求 `content`，`layout`/`visual`/`interact` 可选。

## 2. 节点类别与 Props 正交

区分"逻辑容器 / 布局容器 / 组件"的本质不是 props 形状不同，而是 **kind 解释哪些维度、影响范围是自身还是后代**：

| 类别 | 解释的维度 | 自身几何/视觉 | 影响范围 | 示例 |
|---|---|---|---|---|
| 逻辑容器 | `identity`/行为 | 无（透明） | 后代 | StrategyScope、IdentityScope、FocusScope（声明方向化 entry/exit 端口）、ShortcutScope（局部快捷键映射）、ModalHost、Teleport（portal 提升至顶层渲染）、Group |
| 布局容器 | `layout`（自身+后代） | 有盒，视觉可选 | 后代排列 | Row、Column、Wrap、Frame、Expanded、Spacer、BaselineRow、Stack、Overlay、ScrollView |
| 绘制原语 | `content`+`visual`+`layout` | 有 | 自身 | Text、Image、Rect、NinePatch、Polygon |
| 组件（上层） | 组合以上 | 由组合决定 | 自身+行为 | Button、Input、Table |

- 组件（上层组件套件）的 props 复用基座维度，不发明新维度：

```rust
struct ButtonProps {
    label: Text,             // 内容维度
    layout: LayoutConcern,   // 复用基座类型
    visual: VisualConcern,
    interact: InteractConcern,
}
impl Component for Button { fn render(props, ctx) -> Node { ... } }
```

- 组件 props 里不含 `update_mode`/`key_strategy`，正是「组件无感知」的前提（004-4 的约束天然成立）。
- `ModalHost` 容器本身属于核心契约（M0 定义）：提供模态遮罩、子节点层级排序、点击外部关闭等**基础能力**；页面栈/多路由压栈弹出**管理逻辑**是上层业务组件，不属于内核（见 [010-落地路线](010-落地路线.md) 3.1）。

### 2.1 正交性四条判定

Props 正交 = 每个字段只属于一个维度，不同维度之间零重叠、零互读、零死字段：

| 判定 | 含义 | 违反的样子 |
|---|---|---|
| 一字段一维度 | 同一语义只在一个槽位出现 | `border` 既是布局（宽度参与盒尺寸）又是视觉（颜色） |
| 无死字段 | kind 不解释的维度不接受 | 逻辑容器上设了 `gap` 却被忽略 |
| 独立替换 | 改视觉不影响布局输出；改布局不影响绘制内容类型 | 改 `shadow` 导致布局结果变化 |
| 跨 kind 复用 | 同一维度可被不同 kind 复用 | 圆角定义只属于"按钮"，其他形状用不了 |

### 2.2 新槽位 vs 新 kind

- 新**跨维度**能力（拖拽、tooltip），影响多种 kind → 新槽位。
- 对已有维度的**新解释**（新布局算法）→ 新 kind，尽量复用已有槽位。
- 想给单个 kind 造专属字段 → 危险信号（必成死字段），改走组合。

## 3. 现有模型拆分映射（参考）

从 `punctum-ui` 的 `UiStyle`/`UiContent` 泛化而来，拆分原则即为正交性落地的例子：

| 原字段 | 归属槽位 | 说明 |
|---|---|---|
| `width/height/margin/padding/gap/cross_align/clip/overflow` | `layout` | 纯几何；排版算法由 `NodeKind` 表达 |
| `position`（相对/绝对定位） | 移出首版 | 首版无相对/绝对定位，层级靠树序 + Stack + 页面/模态栈，见 [006-布局引擎](006-布局引擎.md) |
| `border` 的宽度部分 | `layout` | 参与盒尺寸 |
| `border_radius/shadow/visual_offset` | `visual` | 纯外观 |
| `border` 的颜色部分 | `visual` | 不影响盒尺寸 |
| `logical_canvas` | 移出节点样式 | 全局画布配置，不属节点 |
| `Fill/Image/Text` 等通用内容 | `content` | 原语内容 |
| `Weather/RadarChart`、`UiButtonStyle` | 移出基座 | 业务组件，违反「基座不内置业务组件」 |

特例说明：文本的 `font_size` 既影响度量（布局）又影响绘制（视觉），但它属于内容维度、由 Text 叶子同时喂给两个 pass——这是"叶子参与两道流水线"，不是 props 重叠，不算违反正交。

## 4. 节点 id 与身份

- 每棵树有**两类标识**，用途分离：

| 标识 | 生成者 | 用途 | 生命周期 |
|---|---|---|---|
| 结构 id（`node_id`） | 基座内部，构建期分配 | 本帧内查找与命中测试 | 一帧内有效 |
| key（`semantic_key`） | 基座内部（auto 策略）或业务提供（semantic/manual） | 跨帧节点匹配、状态复用 | 跨帧稳定 |

- 结构 id 在构建期按**策略**分配，见 [005-key身份策略](005-key身份策略.md)。
- 结构 id 在一棵树内唯一；非空 key 在一棵树内唯一（auto 策略由基座保证，semantic/manual 由基座校验）。
- **`node_id` 仅本帧有效，禁止用于 `ViewStateStore` 持久存储**；跨帧持久状态一律以 `semantic_key`（key）索引（见 [004-更新策略与状态保持](004-更新策略与状态保持.md) 3）。

## 5. 构建期校验不变量

`UiTree::new`（或等价构建入口）在布局前完成校验，失败返回结构化错误，不 panic：

- 结构 id 与 key 全局唯一，重复自动生成 key 时向上报告。
- 比例尺寸、缩放文本、逻辑画布必须使用非零基数。
- 策略组合合法：更新策略与身份策略只在容器节点声明，向下生效，不要求在叶子重复声明。
- 节点类型与内容形状匹配（例如"文本节点必须有文本内容"由构造 API 限制）。
- 文本内容必须为 UTF-8 编码，非 UTF-8 输入即 `UiBuildError`（系统约束，见 [007-绘制与渲染后端](007-绘制与渲染后端.md) 4.1）。
- 槽位正交性：kind 不解释的槽位不接受（构建器约束），开发期检测可发现死字段。
- 首版无相对/绝对定位字段：构建器不暴露定位 API，层级堆叠仅靠树序 + Stack + 页面/模态栈（见 [006-布局引擎](006-布局引擎.md)）。
- 虚拟列表容器子项必须携带显式 `semantic-id`，缺失即 `UiBuildError`（基座不提供虚拟化默认身份，见 [006-布局引擎](006-布局引擎.md)）。
- Stack 分层校验：`Overlay` 只能是 Stack 的直接子项；Stack 必须有至少一个参与尺寸推导的普通子项（见 [006-布局引擎](006-布局引擎.md) 4）。
- 线性分配校验：`Expanded`/`Spacer` 只能是 Row/Column 的直接子项；Wrap 禁止二者，避免换行与剩余空间的回溯依赖（见 [006-布局引擎](006-布局引擎.md) 3）。
- 对齐校验：非默认 `cross_align` 只能由 Row/Column 使用；基线排列使用独立 `BaselineRow`。
- 尺寸校验：`Size::Constrained(MinMax)` 禁止包裹 `Fixed`、`min > max`、嵌套 `MinMax`，均即 `UiBuildError`（见 [006-布局引擎](006-布局引擎.md) 5）。
- 焦点图静态隔离：父 `focus_graph` 引用子 Scope 内部节点 id 即 `UiBuildError`，仅允许连接子 Scope 的方向化 `.entry_*`/`.exit_*`（端口契约见 [008-交互焦点与宿主接口](008-交互焦点与宿主接口.md)）。
- 方向化端口校验：`entry_*`/`exit_*` 只能绑定本 Scope 内部焦点 id；方向无关 `entry`/`exit` 展开为四方向同绑；绑定目标必须为可聚焦节点。
- Teleport 校验：属逻辑容器、无自身盒尺寸（构建器不暴露 layout）；**禁止嵌套 Teleport**；仅能绑定自身内部 source 锚点（见 [008-交互焦点与宿主接口](008-交互焦点与宿主接口.md) 2.10）。

校验结果类型：`UiBuildError`（无效树数据）、`UiLayoutError`（布局无法满足最小尺寸）。

## 6. 纯操作保证

`resolve` 必须是**纯操作**：相同输入必定得到相同的 `UiFrame`。签名：

```
fn resolve(
    node: &UiNode,
    viewport: Viewport,
    text_measurer: &impl TextMeasurer,
    scroll_inputs: &HashMap<SemanticKey, ScrollState>,
) -> UiFrame
```

- `viewport`：逻辑画布尺寸，保存在输出的 `UiFrame` 中（见 7）。
- `text_measurer`：不可变文本度量接口，文本 Auto 尺寸与换行依赖它。**必须是纯函数**——相同输入（字符串、字号、字体参数）输出固定 `TextMetrics`，不持有可变运行时状态；软件光栅、wgpu、宿主各自实现该 trait（见 [007-绘制与渲染后端](007-绘制与渲染后端.md) 4.0）。
- `scroll_inputs`：各滚动容器的当前滚动偏移，**外部只读输入**，`resolve` 不持久保存（见 [006-布局引擎](006-布局引擎.md) 6）；跨帧记忆由 M4 视图状态仓库承担。

这保证：

- 离线渲染与线上渲染结果一致；
- 单元测试可离线复现任何一帧；
- 截图输出可做 snapshot 测试。

实现约束：布局与绘制过程不得读取外部可变状态；时钟、随机数、设备输入一律不进 `resolve`。

## 7. 绘制结果

`resolve` 输出 `UiFrame`，**自包含逻辑画布尺寸**：

```
pub struct UiFrame {
    pub viewport: Viewport,          // resolve 输入的 viewport，帧自描述
    pub commands: Vec<DrawCommand>,
    pub hit_regions: Vec<HitRegion>,
    pub scroll_bounds: Vec<ScrollBounds>,
}
```

- `commands`：有序绘制命令（顺序即 z 序，后绘制者在上）；每条携带**预合并 clip rect**（祖先裁剪区域求交，见 [007-绘制与渲染后端](007-绘制与渲染后端.md) 2）。
- `hit_regions`：命中区域，按树顺序产生；反向遍历选中最上层命中的区域；携带同一预合并 clip，命中测试做点-in-rect 即可。
- 命中区域携带 `node_id`，供交互层映射回视图状态与宿主动作。
- `scroll_bounds`：每个滚动容器的稳定 key、裁剪视口、完整内容尺寸与最大偏移；renderer 忽略它，宿主用它钳制写回 `ViewStateStore` 的 `ScrollState`，不再重复猜测列表行数或内容高度。
- `viewport` 自包含：序列化保存后可喂给任意后端（raster/wgpu/canvas）复现，无需外部再记画布尺寸（业界同类：Flutter 渲染帧自描述视口）。

## 8. 规则

- ✅ 树为值语义，基座不持有可变的"当前树"。
- ✅ 维度槽位正交：一字段一维度、无死字段、独立替换、跨 kind 复用。
- ✅ 逻辑容器零几何；布局容器只谈排列；组件复用基座维度不发明新维度。
- 🔧 结构 id 与 key 构建期唯一性校验，重复即 `UiBuildError`。
- 🔧 `resolve` 为纯操作，禁止读取时钟/随机数/设备输入。
- 🔧 可变视图状态不得进入 `UiNode`。
