# 013-决策日志

> 集中记录 tela 设计期的关键决策（ADR）：结论、背景理由、落点文档。新增决策一律追加到本文，便于回溯与评审。
> 状态标注：✅ 定案（写入文档）/ 🔧 草案（实现期校准）。

## 1. 项目定位与架构

| ID | 决策 | 结论 | 落点 |
|---|---|---|---|
| D01 | 项目形态 | 全新独立 Rust 单代码库项目，参考 `punctum-ui` 渲染器无关思路，不复制代码；四类界面（游戏 HUD/游戏内编辑器/B 端/C 端）共享一套基座 | 001、002 |
| D02 | 命名 | `tela`（拉丁语"画布/织布"） | README |
| D03 | 分层 | 四层依赖：契约 → 核心 → 适配 → 宿主；core 纯 Rust、`forbid(unsafe)`、零平台依赖、`resolve` 纯函数 | 002、003 |
| D04 | Props 正交 | 维度槽位模型：`UiNode` 拆五槽位（layout/visual/interact/identity/content），构建器按 kind 限制合法组合，一字段一维度 | 003 |

## 2. 布局

| ID | 决策 | 结论 | 落点 |
|---|---|---|---|
| D05 | 相对/绝对定位 | 首版**完全砍掉**；层级靠树序 + Stack + 页面/模态栈 + visual 偏移；FreeCanvas/局部绝对定位留 v1.1 | 006 §4 |
| D06 | z-index | 首版**不新增 z-index 数值维度**；`DrawOrder` 容器内局部、Teleport 跨父盒、ModalHost 全局栈三层互补 | 006 §4、007 |
| D07 | 栅格 Grid | 首版**砍掉**（行列轨道、跨行跨列），未来扩展 | 006 §1、011 |
| D08 | Flow/Flex | **已被 D57 取代**：曾统一单 Flex + `wrap` 开关；v2 改用独立 `Row`/`Column`/`Wrap` 原语，避免字段组合和回溯测量。 | 006 §3、D57 |
| D09 | Stack 尺寸 | **已被 D57 取代**：曾以 `FillOverlay` 字段分层；v2 改为 `Overlay(OverlaySpec)` 包装器，普通内容与浮层在树结构中可见。 | 006 §4、D57 |
| D10 | MinMax | **修饰包装器**而非独立尺寸模式：`BaseSize` + `MinMax{base,min,max}` + `Size{Raw|Constrained}`；三层解析（基准 → 本地钳制 → 父 Constraints）；禁包 Fixed、禁嵌套、min>max 构建报错 | 006 §5 |
| D11 | clip 表示 | **每条 DrawCommand 携带预合并 clip rect**（祖先裁剪求交），后端不维护裁剪栈，命中区域同带 | 007 §2 |
| D12 | 虚拟列表 item 尺寸 | 首版仅定高 item；变高配独立 item 尺寸缓存池（`semantic-id` 为 key），v1.1 落地 | 006 §6、004 §7.4 |
| D13 | 布局缓存 | ✅ 叶子测量缓存与 Dirty 子树 `LayoutBox` 缓存均已落地，均在 child 收到最终约束后查询；未来 `LayoutBoundary` 只能包装现有调度，不能另起预测/重测路径。缓存不破坏 resolve 纯函数 | 004 §7、D57 |

## 3. 身份与更新

| ID | 决策 | 结论 | 落点 |
|---|---|---|---|
| D14 | 虚拟列表身份 | 虚拟列表 item **强制显式 `semantic-id`**，无默认身份语义；业务手动管理全量数据，虚拟列表只负责可视区渲染 | 006 §6、005 |
| D15 | key 策略 | 4 种：`auto-path`（默认）/`auto-stable-identity`/`semantic-id`/`manual`；重复 key 与策略误用开发期显性告警 🔧（auto-stable-identity 算法实现期校准） | 005 |
| D16 | 视图状态索引 | `ViewStateStore` 以 `semantic_key`（跨帧稳定 key）索引；`node_id` 仅本帧有效、禁止用于持久存储 | 003 §4、004 §3 |
| D17 | 滚动偏移 | 运行时交互状态、不作为布局输出；`resolve` 以 `scroll_inputs` 外部只读输入；跨帧记忆归 M4 ViewStateStore | 006 §6、003 §6 |

## 4. 焦点与输入

| ID | 决策 | 结论 | 落点 |
|---|---|---|---|
| D18 | 焦点模型 | **彻底舍弃空间四向最近邻**；组件树 + 规约式状态转移（焦点图），转移纯函数、可静态推导、不依赖布局 | 008 §2 |
| D19 | 规约解析 | 三级来源（容器自动生成 → 默认树关系 → 业务显式规约），**替换覆盖语义**：显式规约替换该 `(节点,输入)` 全部自动规则，单输入唯一目标 | 008 §2.2 |
| D20 | 边界穿越 | 容器边界处方向键**默认回退父作用域按树序解析**，父零配置；方向化端口用于精确控制 | 008 §2.2/2.9 |
| D21 | entry/exit 端口 | **方向化端口契约**：`entry_*`/`exit_*` 按方向绑定、方向无关简写=四方向同绑、父图禁引用子 Scope 内部 id（构建期检查）、`unsafe_internal_ref` 逃逸口子（Linter 警告） | 008 §2.9 |
| D22 | 取消键终止 | 焦点在模态内 → 先关当前模态；否则沿树回退最近焦点组出口 | 008 §2.3/§3 |
| D23 | Teleport 焦点 | Teleport 子树焦点遍历链**迁移至 ModalHost**（对齐 Flutter Overlay），脱离原逻辑树；semantics 保留原始位置 | 008 §2.10 |
| D24 | 绘制≠Tab | DrawOrder 不改焦点遍历；Tab 顺序用 `tab_index`（InteractConcern 整数，-1 移出序列）独立调整 | 008 §2.10 |
| D25 | FocusTrap | core 仅提供 `FocusScope.trap_focus`（Scope 内 Tab 循环）；ESC/点击外部/自动聚焦/关闭恢复由上层 tela-widgets 封装 | 008 §2.10 |
| D26 | 焦点保存/恢复 | `UiAction::SaveFocus`/`RestoreFocus` 显式原语，无自动隐式恢复；焦点迁移上层发起 | 008 §2.10 |
| D27 | 快捷键（已被 D54 取代） | 历史方案：物理键位/语义动作分离（`KeyCombo`→`ShortcutId`）；`ShortcutScope` 内持有局部映射并冒泡。该方案不能支持运行时应用键位表，保留仅用于迁移回溯。 | 008 §2.11、D54 |

## 5. 渲染与文字

| ID | 决策 | 结论 | 落点 |
|---|---|---|---|
| D28 | 字体栈 | `ab_glyph`（解析/度量）+ `ab_glyph_rasterizer`（栅格化）；度量是"同一不可变字体数据"的纯函数，各后端挂载同一字体文件 | 007 §4.0 |
| D29 | 字符集约束 | 文本一律 UTF-8；字形/度量只保证中英文，超范围由上层降级、基座不崩溃 | 007 §4.1 |
| D30 | 降级位置 | UiFrame 为**后端无关完整指令集**（可序列化复现）；特效降级是各后端消费时的本地行为（按自身 `BackendCapabilities` 预处理） | 007 §3 |
| D31 | raster 定位 | 仅测试/CI/离线导出/服务端，不做线上渲染；**像素基准**（取整规范以 raster 为准）；无 GPU、no_std；内置能力集固定（高斯阴影/径向渐变/复杂蒙版/子像素降级） | 007 §7 |
| D32 | UiFrame 自包含 | `UiFrame` 携带 `viewport`，raster 从帧读取画布尺寸，`RasterConfig` 不再重复传 viewport_size | 003 §7、007 §7.2 |
| D33 | no_std 预案 | M3 前期验证 ab_glyph 依赖链 no_std+alloc；不可行则拆 feature（std 动态字形 / no_std 预渲染位图字形子集）🔧 | 007 §7.10 |

## 6. 状态与绑定

| ID | 决策 | 结论 | 落点 |
|---|---|---|---|
| D34 | 业务绑定 | `BindId` 挂 `InteractConcern`，`UiAction::ValueChange(BindId, Value)` 唯一业务变更通道；core 仅透传标识；响应式/Signal 运行时禁止进 core/adapter，由宿主与 tela-widgets 实现 | 012 |
| D35 | 状态隔离 | 视图临时状态（ViewStateStore）与业务表单状态（宿主持有、BindId 映射）严格隔离、互不干扰 | 004 §3、012 |
| D36 | Teleport 悬浮 | `Teleport` 逻辑容器：portal 不参与父布局、帧生成提升至 ModalHost 顶层队列；锚点/鼠标偏移为纯视觉偏移；禁嵌套、仅绑内部 source；点击外部仅抛 `TeleportClickOutside` 由宿主关闭 | 008 §2.10、§3 |

| D52 | `tela-ui` 第一阶段 | ✅ `Form`/`Table`/`Select`/`Cascader` 从 widgets 直接迁移到 `tela-ui`，不保留 re-export；`Toolbar` 以 `UiIntent::Invoke` 输出命令，demo Controller 解包后继续持有业务命令。自动追踪、Scheduler、CacheScope 与复杂 overlay 留待后续阶段。 | 017、`crates/tela-ui` |
| D53 | 文件管理器视觉与图标系统 | 被 D56 取代：产品 UI 继续使用 Material Symbols Rounded 受控子集、双层客户端栏和上下文命令分组，但图标不再归 widgets。 | 019 |
| D54 | 动态键位表与键盘意图 | ✅ 原始物理键、`KeymapSnapshot` 和 `KeyboardIntent` 三层分离；键位表归宿主/应用并支持校验后的运行时整表替换；UI 树只声明 `KeymapScopeId`；core 只消费意图并按焦点图规约。ABI v2 已将键位表替换放入跨平台 event；WebView 人工验收仍由开发者在真实浏览器完成。 | 008 §2.11、020 §3-§4、023 §5 |
| D55 | 基线与可见焦点 | ✅ `TextMetrics`、布局盒与文本绘制命令传递真实首行基线；文字基线由 `BaselineRow` 表达；当前焦点和默认焦点身份归 core 的 `UiTree`/`ViewStateStore`，虚拟列表及其他 core 无法可靠推导实体身份的例外复用业务 `semantic-id`；core 生成不影响布局/命中的 FocusRing，应用完整消费 Hover 进入、离开与树重建失效；WebView 真机视觉验收不由构建命令伪造。 | 005 §2.5、008 §2.1、020 §3/§5-§6、023 §9 |
| D57 | 布局 v2 / 单次测量 | ✅ 删除兼容性 `Flex` API 与 `Fill` 尺寸模式，排版模式升级为 `NodeKind` 原语。`Row`/`Column` 分阶段调度自然项与分配项，`Wrap` 仅自然布局，`Frame` 显式盒，`BaselineRow` 专管文字基线，`Overlay` 专管 Stack 浮层。一次根级 measure 内每个源节点最多一次；Dirty 缓存复用同一最终约束调度。 | 006、004 §7、`tela-contract`/`tela-core` |
| D56 | 图标原语与行内内容 | ✅ `tela-core` 只提供通用 `VisualConcern::visual_offset`，其作用域仅为 draw 命令和文本 `baseline_y`，不改变布局、命中、clip 或 key。新建 `tela-icon` 承载 `IconKey`、provider、Material iconfont 映射与基于 `GlyphInkMetrics` 的光学校正；不增加 Icon 节点/绘制协议。`tela-widgets::Button` 接受任意内容，`tela-ui::Text`/`InlineSlot`/`IconButton` 组合图标与文字；旧 `IconLabel` 和 widgets 图标 API 直接删除。SVG provider 待全后端 `VectorPath`/`Picture` 原语后再做，禁止借用 `CustomDraw`。 | 021、007 §4.4、`crates/tela-icon` |
| D58 | WebView 统一 bundle / WGPU 壳 | ✅ 浏览器成为 `tela-webview-sdk` 的 Rust+JS 胶水壳：固定 shell 以 no-store 读取与原生壳相同的 `.tela`，在 Rust 校验 ABI/archive 后以浏览器 WebAssembly 执行 guest，并用 WGPU 呈现 `UiFrame`。产品页不再直载 demo wasm、不提供 raster 回退；`rawgpu.html` 只做环境诊断。DOM IME、物理键和生命周期停留在 SDK JavaScript 半边，应用仍拥有键位表和业务状态。 | 007 §6.1、022、023、025 |
