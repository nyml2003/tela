# 019-文件管理器视觉与图标系统实施目标

> **状态：✅ 已完成。**  
> **前置：** [014-文件管理器演示与组件运行时](014-文件管理器演示与组件运行时.md) 的全视口、MVC 与交互链路已经完成；[015-tela-ui 与局部交互状态](015-tela-ui与局部交互状态.md) 定义组件分层边界。本阶段只改善现有文件管理器的视觉层级与组件基础设施，不扩展文件业务能力。

## 1. 目标

将 `tela-demo` 的文件管理器从“用于验证交互链路的工具界面”提升为现代原生客户端风格的工作区：

- 画布仍严格占满视口，只有导航、文件列表、缩略图和预览区域可内部滚动；
- 顶部由多条窄栏收敛为全局栏与工作栏两层，信息层级清楚且不模拟网页内容流；
- 命令依照业务上下文分组，避免一排同权重、无选择时不可用的按钮；
- 产品 UI 统一使用 Material Symbols Rounded iconfont，替代当前“文件夹/文本/图片”等文字类型徽标；
- 图标的资源、原子控件与组合模式有清楚的 crate 归属，并在 CPU、Canvas 和 WGPU 路径中一致渲染；
- 不改变现有 `UiIntent -> Controller -> Model/Session` 链路、Signal/Dirty 刷新策略或组件免 key 调用约束。

本阶段是视觉与组件基础设施工作，不接入真实文件系统、网络资源或浏览器图标服务。

## 2. 已确认决策

| 主题 | 决策 |
| --- | --- |
| 视觉方向 | 现代原生客户端：浅灰工作区、白色内容面、蓝色强调、低饱和状态色、细分隔线；圆角最大 8px，不使用装饰性阴影或卡片堆叠。 |
| 顶部结构 | 采用双层客户端栏：52px 全局栏放品牌、搜索与窄屏目录入口；44px 工作栏放路径、文件命令和视图控制。状态栏继续存在。 |
| 品牌 | `TELA 文件` 从深色整条顶栏退为轻量品牌信号，不以高饱和深色覆盖整个应用顶部。 |
| 操作层级 | “新建”是常驻主操作；选择文件后才显示重命名、复制、移动、收藏、标签、删除等上下文操作；回收站范围才显示恢复。 |
| 图标来源 | 采用 Material Symbols Rounded 的受控 TTF 子集，固定 `FILL=0`、`wght=400`、`GRAD=0`、`opsz=24` 的轮廓风格。 |
| emoji | 产品 UI 不使用 emoji 作为图标；emoji 只作为用户文件名或文件内容的一部分原样显示。 |
| 发现性 | 窄屏纯图标按钮的名称通过既有状态栏悬停反馈显示；本阶段不新增 Tooltip/Popover 浮层。 |
| 组件边界 | `tela-widgets` 提供 `Icon`/`IconButton` 原子控件；`tela-ui` 负责 Toolbar 等组合模式；`tela-demo` 持有文件领域到通用图标的映射。 |
| 范围控制 | 不新增右键、拖放、多选、路径历史、菜单系统、浮层系统或新的文件操作。 |

## 3. 现状问题与视觉规则

当前演示已经满足全视口、内部滚动和基础交互要求，但视觉上仍存在以下问题：

- 顶栏、工具栏、路径栏连续堆叠，形成多条竞争的细横带；
- 多数工具栏动作都使用相同的深色填充，即使无选择时也以禁用按钮占据空间；
- 侧栏的范围切换与目录树缺少明确分组，文字类型徽标又大又抢眼；
- 文件表格的边界线过重，选中、悬停、禁用和危险操作的视觉节奏不够一致；
- `FontRef` 已存在于帧协议，但演示后端尚未按字体引用选择字形，无法可靠接入 iconfont。

本阶段采用以下不可变规则：

- 工作区底色使用浅灰，详情区和列表使用白色；边界以低对比中性色表达，不用阴影制造层次；
- 文本使用深色主信息与中性次信息；蓝色只用于选中、主操作和可识别的活动状态；危险操作只在语义需要时使用红色；
- 文件类型图标无彩色文字底板：文件夹为蓝色、文本为中性蓝灰、图片为紫色、归档为琥珀色；
- 导航行、文件行和命令控件都必须有独立的 hover、selected、disabled、danger 状态，不能仅靠文字或颜色表达；
- 宽屏命令以“图标 + 文字”为主，窄屏收缩为图标；文件表格在窄屏继续按既有断点隐藏次要列；
- 不使用 emoji、Unicode 符号或矩形中文字作为产品图标，也不以几何图元拼装图标。

## 4. 页面与交互设计

### 4.1 固定布局

```
+----------------------------------------------------------------+
| 全局栏 52：轻量品牌、全局搜索、窄屏目录入口                    |
+----------------------------------------------------------------+
| 工作栏 44：面包屑、主操作、上下文操作、视图/排序/筛选、撤销    |
+----------------------+-----------------------------------------+
| 目录树                | 详情区                                  |
| 宽屏 264              | 文件列表/缩略图，或只读代码/媒体预览      |
| 内部滚动              | 内部滚动                                |
+----------------------+-----------------------------------------+
| 状态栏 28：选择数、目录项数、操作反馈、悬停命令说明            |
+----------------------------------------------------------------+
```

- 宽度 `>= 1200` 显示 264px 侧栏；宽度 `< 1200` 继续使用既有叠加目录抽屉，不压缩详情区；
- 宽度 `< 900` 时，工作栏的次要命令变为纯图标，文件表格继续隐藏修改时间等次要列；
- 面包屑归入工作栏，不再单独占据第三条横栏；详情摘要保留在内容区顶部，不承担路径导航；
- 详情区的空白是工作区本身，不添加填充性卡片、插图或假数据。

### 4.2 命令分组

工作栏按以下顺序投影，所有命令继续输出既有 `IntentTarget`：

1. 面包屑与当前目录；
2. 常驻主操作“新建”；
3. 仅在已选择条目时出现的上下文操作：重命名、复制、移动、收藏、标签、删除；
4. 仅在回收站范围且已选择条目时出现的“恢复”；
5. 右侧全局控制：当前视图模式、当前排序字段、当前筛选范围、撤销。

未选择条目时不显示一串禁用操作。视图、排序和筛选必须显示当前值，而不能只显示笼统的“视图”“排序”“筛选”。删除保留现有确认流程；本阶段不改变命令去重、撤销或业务校验。

### 4.3 导航、摘要与列表

- 侧栏先显示“快速访问”范围，再显示“目录”树；分组标题使用小型次要文本，不再使用彩色文字徽标；
- 导航和目录行使用 18px 图标、32px 行高、左侧缩进表达层级；选中行使用浅蓝背景与主色文字；
- 详情摘要使用 24px 文件类型图标、名称和元信息，避免以大面积类型色块争夺注意力；
- 表头使用浅色底与中性文本，列表行提升至 32px，分隔线降为低对比；选中使用浅蓝填充，hover 使用中性浅底；
- 文件类型列保留文字分类，图标只承担快速识别，不能成为唯一信息来源；
- `IconButton` 的 hover 名称投影到状态栏右侧，和既有 `hovered_target` 生命周期一致，不需要页面自行管理 key 或局部状态。

## 5. 图标、字体与组件边界

### 5.1 资源层

新增 `tela-fonts` 作为无依赖资源 crate。它只提供内嵌字体的稳定名称和只读字节：

- `tela-ui`：现有 WQY 中文正文字体；
- `tela-icons`：Material Symbols Rounded 受控子集；
- 对未知 `FontRef` 回退为 `tela-ui`，不因缺失字体中断布局或渲染；
- 字体文件、来源记录和 Apache-2.0 许可证随仓库提交；子集只包含本阶段 `IconName` 实际使用的字形。

该 crate 不依赖 `tela-core`、renderer、widgets 或 demo。它避免 renderer 反向依赖 `tela-widgets`，也避免把具体 UI 资源塞进 `tela-core`。

### 5.2 原子与分子组件

`tela-widgets` 新增以下公开原子能力：

```rust
pub enum IconName {
    Add, Delete, Edit, Copy, Move, Restore, Favorite, Tag, Undo,
    Search, Folder, FolderOpen, Document, Image, Archive,
    AllFiles, Trash, List, Grid, Sort, Filter, ChevronRight, Menu,
}

pub struct Icon;
pub struct IconButton;
```

- `Icon::new(IconName)` 生成使用 `FontRef("tela-icons")` 的单个文本原语，支持尺寸与颜色；字形码位映射是 `tela-widgets` 私有实现；
- `IconButton` 复用 Button 的 hover、selected、disabled、危险语义与 `BindId` 接口，支持图标、可选标签和紧凑尺寸；它不持有业务状态或 tela key；
- `tela-ui::ToolbarItem` 接收可选 `IconName`、语调、激活态和标签可见策略，负责宽/窄屏命令投影；它不包含文件种类、文件命令名或 Controller；
- `tela-demo` 的 presentation 层将 `EntryKind` 映射到 `IconName` 与领域配色，继续通过 `IntentTarget` 把命令交给 Controller。

### 5.3 后端字体闭环

`FontRef` 是 `UiFrame` 的既有字段，本阶段只补齐其消费：

- raster 与 WGPU 按 `FontRef` 从 `tela-fonts` 取得对应字节，并分别缓存解析后的字体；
- Canvas2D 的 `fill_text` 入口增加 `FontRef` 并由 mock 覆盖转发；实际浏览器 demo 当前选择 raster
  或 WGPU 路径，后续 Canvas 宿主实现必须以同一 `FontRef` 选择对应受控字体；
- Demo 的 `TextMeasurer` 使用与渲染一致的字形数据；图标按 1em 方形度量，防止图标列和命令按钮布局漂移；
- `tela-render-raster` 的 `no_std` 路径维持既有缺字方块降级；浏览器文件管理器不把它作为 iconfont 可用性的验收路径；
- 不修改 `tela-contract`、`tela-core` 或资源协议的所有权边界。

## 6. 实施顺序

1. 增加 `tela-fonts`、Material Symbols Rounded 子集和许可证，更新 workspace 依赖方向规则；
2. 让 raster、WGPU、Canvas 与 Demo 度量器按 `FontRef` 选择字体，并为 iconfont 建立跨后端测试；
3. 在 `tela-widgets` 落地 `IconName`、`Icon`、`IconButton`，再扩展 `tela-ui::ToolbarItem`；
4. 在 `tela-demo` 的 shared、shell、navigation、detail 组件中替换文字徽标，完成双层顶栏、上下文命令和列表视觉调整；
5. 更新 [014](014-文件管理器演示与组件运行时.md)、[007](007-绘制与渲染后端.md)、[015](015-tela-ui与局部交互状态.md) 与本文的完成状态，确保文档不把计划误写成现状。

页面仍保持 `application`、`domain`、`host`、`presentation` 的现有物理结构；不得为了视觉改版将布局、图标映射、业务命令和资源加载堆入单个文件。

## 7. 验收标准

### 7.1 组件与字体

- `IconName` 的每个本阶段成员都有稳定的 glyph 映射；`Icon` 使用 `tela-icons` 且生成可测的文本节点；
- `IconButton` 的普通、悬停、选中、禁用与危险状态不回归 Button 的现有行为；
- `ToolbarItem` 在宽屏投影图标加标签、窄屏投影图标，并保持 `UiIntent::Invoke` 路由不变；
- raster 与 WGPU 能将至少一个 `tela-icons` 字形栅格化为非透明像素；Canvas mock 验证字体引用被转发；
- Demo frame trace 能观察到 `tela-icons`，正文仍使用 `tela-ui`。

### 7.2 交互与视觉

- 在 1440px、1199px、899px 检查双层顶栏、侧栏/目录抽屉、命令收缩、表格列收缩和状态栏悬停说明；
- 浏览器 canvas 继续填满 CSS 视口，页面不产生滚动条，DPR 改变后输入与渲染仍对齐；
- 目录切换、文件选择、搜索、视图切换、排序、筛选、操作弹窗、删除确认、恢复和撤销不回归；
- 宽屏截图中不再出现文字类型徽标、深色整条顶栏或无选择时的一排禁用文件操作。

### 7.3 工程门禁

本次实现完成后执行：

```bash
node ops/src/interface/cli.ts check
node ops/src/interface/cli.ts build all --gpu
node ops/src/interface/cli.ts verify demo
cargo fmt --all -- --check
git diff --check
```

CPU 与 WGPU 浏览器路径都需要人工截图验收；仅通过无窗口构建或 GPU 自检不能证明视觉完成。

## 8. 非目标

- 不把 Material Symbols 全量字库或第三方在线图标服务引入运行时；
- 不实现 Tooltip、Popover、Menu、右键菜单、拖放、多选、路径历史或快捷键扩展；
- 不引入主题切换、动态设计令牌、动画框架或装饰性视觉效果；
- 不让 `tela-ui` 直接依赖 renderer/demo，不让 widgets 或页面调用方管理 tela key；
- 不将本阶段计划写入 [016-已解决问题归档](016-已解决问题归档.md)；只有源码、测试和门禁完成后才可归档。
