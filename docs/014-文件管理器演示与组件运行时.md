# 014-文件管理器演示与组件运行时

> **状态：✅ 已实现范围。** 本文定义以文件管理器为载体的复杂客户端演示，
> 用来验证 tela 的全视口宿主、组件契约、MVC 边界与局部 Dirty 刷新；它不是 tela 核心
> 对外承诺的业务功能，也不接入真实文件系统。

## 1. 目标与边界

文件管理器演示应是一个占满客户端工作区的应用，而不是随浏览器文档流无限下滚的网页：

- canvas 的 CSS 尺寸始终等于 `100dvw x 100dvh`，`html`/`body` 不产生页面级滚动；
- `UiFrame.viewport` 直接采用当前 CSS 视口逻辑像素；canvas backing store 按
  `devicePixelRatio` 更新，CPU 与 WGPU 后端都消费同一逻辑帧；
- 只有目录树、目录中的文件列表/缩略图网格、文本预览允许内部滚动；
- 数据源为仓库内稳定的内存模拟工作区，所有文件操作只修改内存 Model；不请求浏览器目录
  权限，不读写本地文件系统，也不引入网络；
- 文本文件为只读代码预览，不包含编辑、选区、复制、剪贴板或富文本编辑能力；
- 首版不增加右键、Ctrl/Shift 范围选择、拖放、锚定下拉菜单或路径历史。选择为单选；新建、
  重命名、移动到示例“设计”目录、标签和删除走明确的工具栏控件与居中 modal，复制、收藏和
  恢复为立即写入内存 Model 的可撤销命令。

## 2. 客户端应用壳

### 2.1 固定区域

应用按纵向固定区域组成，所有尺寸为逻辑像素：

```
+----------------------------------------------------------------+
| 顶栏 48：工作区名称、全局搜索、导航/设置                        |
+----------------------------------------------------------------+
| 工具栏 40：新建、重命名、复制、移动、删除、收藏、视图切换        |
+----------------------------------------------------------------+
| 路径栏 36：工作区面包屑、当前目录                                |
+----------------------+-----------------------------------------+
| 目录树                | 详情区                                  |
| 宽屏 264              | 目录列表/缩略图，或只读代码/媒体预览      |
| 内部滚动              | 内部滚动                                |
+----------------------+-----------------------------------------+
| 状态栏 28：选中数、当前目录项数、操作反馈                        |
+----------------------------------------------------------------+
```

- 宽度 `>= 1200`：显示 264px 目录树；详情区填充剩余空间。
- 宽度 `< 1200`：收起目录树，由顶栏导航按钮打开叠加式目录抽屉；详情区保持原宽度，不被
  抽屉压缩。
- 宽度 `< 900`：文件详细列表隐藏修改时间、大小等次要列，工具栏只保留图标及必要文字，
  目录/文件摘要保留。
- 不以整页比例缩放替代响应式布局；窗口变更必须以新 viewport 重新构建布局。

### 2.2 视觉规则

- 采用现代系统工具风格：浅灰工作区、白色内容面、蓝色强调、低饱和状态色、细分隔线；
  圆角最大 8px，避免卡片堆叠和装饰性阴影。
- 首版以统一的紧凑类型徽标表达文件、目录、标签和状态；真正的图片缩略图与图标资源不属于
  本演示，避免为未接入的 asset pipeline 伪造加载语义。
- WGPU 演示只使用当前已支持的纯矩形、圆角矩形、文本和图片；分隔线使用独立矩形，
  不依赖尚未实现的描边、渐变或阴影。
- 选中、悬停、键盘焦点、禁用、危险操作必须各自可辨识，不能仅依赖颜色；Tab 顺序与视觉
  顺序一致。

## 3. MVC 与组件契约

### 3.1 职责

```
Input -> tela-core -> UiAction -> Controller -> Model/Session Signal
                                                   |
                                                   v
                      ComponentRuntime <- 依赖追踪 <- Component View
                                                   |
                                                   v
                                 UiNode subtree -> resolve_dirty -> UiFrame
```

| 层 | 持有内容 | 禁止内容 |
|---|---|---|
| Model | `EntryId` 稳定的目录树、文件内容、缩略图、标签、收藏、回收站、可撤销命令历史 | tela 节点 key、焦点、滚动、平台 I/O |
| Session | 当前目录、查询、排序、筛选、视图模式、目录展开、对话框状态 | 文件实体的唯一事实来源 |
| Controller | `UiAction -> Intent -> Command` 分发、Model/Session 的唯一写入口 | 直接组装页面 `UiNode`、直接访问 renderer |
| View Component | 从 props/signal 快照声明式生成 `UiNode`，声明可发出的 intent | 写业务状态、读写更新策略、平台副作用 |
| ComponentRuntime | signal 订阅、应用组件边界的 dirty 批处理 | 业务命令、core 内部状态 |

### 3.2 组件最低契约

顶层可组合组件使用明确的 Rust trait/struct 契约：

```rust
trait Component<Props> {
    fn render(&self, props: &Props) -> UiNode;
}
```

- `Props` 是只读输入快照。普通组件不暴露 `key()`，不构造 `SemanticKey`，也不在普通节点上
  写 `IdentityConcern`；节点身份默认全部交给 tela-core 的 `auto-path` 与
  `auto-stable-identity` 分配。
- runtime 使用不可见的**组件实例路径**登记 signal 依赖和 dirty 状态。该路径仅用于 runtime
  找回待重建的 View 分支，不透传为 tela 节点 key，不参与 `ViewStateStore` 或业务 Model。
- 数据项统一使用 `EntryId`，但它不是业务组件要管理的 tela key。只有 `VirtualList`、
  `FileList`、`ThumbnailGrid` 这类集合组件在内部把 `EntryId` 映射为虚拟列表所必需的
  `semantic-id`；页面和 item 组件的调用方不接触这项映射。这是定高虚拟列表的框架约束，
  不能由 auto-path 替代。
- `bind_id` 是业务意图路由值，不是 tela key。Controller 在 `intent_from_bind_id` 中统一解析
  `bind_id -> Intent -> Command`，普通组件只声明自己能触发的绑定值。
- `AppShell` 是当前 trait 的实现；区域组件以私有渲染函数拆开，避免单文件堆叠。组件不得读取
  或切换 `UpdateMode`，由页面祖先的 Dirty 作用域统一配置。
- 组件状态若是焦点、滚动、悬停、选择等临时视觉状态，使用 `ViewStateStore`；文件、标签、
  收藏与操作历史只在 Model 中。

### 3.3 Solid 风格刷新策略

现有 `Signal` 只能显式订阅，`UiTree::resolve_dirty` 已能按 stable key 重用未变化的布局。为
了把二者连接起来，在 `tela-widgets`/宿主层新增同步的 `ComponentRuntime`：

1. 宿主为组件路径显式订阅 `Signal`；路径不映射为 tela 节点 key。
2. signal 写入后，runtime 将依赖路径标记 dirty；同一事件循环内重复通知在集合中合并。
3. 当前演示以 `app.shell` 为投影边界：下一帧重新投影 shell，但不把响应式机制放进 core。
4. 宿主跨帧持有 `LayoutCache` 并以 `resolve_dirty` 布局；core 根据自动身份、内容指纹和约束
   重用未变化的布局盒。只有虚拟列表 item 使用集合组件内部生成的稳定数据身份。

这不是把响应式运行时放入 `tela-core`：依赖追踪、订阅与批处理只存在于 widgets/宿主层；
`UiTree`、`resolve_dirty` 与 renderer 继续是纯输入到输出的实现。

## 4. 页面组件与交互

| 组件 | Props / 状态来源 | 内容与意图 |
|---|---|---|
| `AppShell` | Session、viewport | 固定区域和响应式断点；打开目录导航、全局搜索 |
| `DirectoryTree` | 工作区树、当前目录、筛选范围 | 目录、全部文件、收藏、标签、回收站；切换目录或范围 |
| `CommandToolbar` | 选择集、当前目录、视图模式 | 新建、重命名、复制、移动、删除、收藏、视图切换、撤销 |
| `PathBar` | 当前目录 | 工作区面包屑和当前目录 |
| `DirectoryDetail` | 当前目录、查询、排序、筛选、选择集 | 内联目录摘要、详细列表/缩略图网格、选择文件 |
| `FileList` | 当前可视窗口、排序后的文件项 | 固定行高虚拟列表、单选行、类型徽标、名称、类型、修改时间、大小 |
| `ThumbnailGrid` | 当前可视窗口、缩略图 | 固定高度卡片行的虚拟列表；不引入 Grid 容器 |
| `TextPreview` | 文件文本、滚动状态 | 等宽文字、行号、只读虚拟滚动 |
| `AssetPreview` | 图片或非文本文件信息 | 类型化占位预览 |
| `InlineSummary` | 选中目录/文件 metadata | 名称、路径、类型、大小、修改时间、标签、收藏状态；固定于详情区顶部 |
| `OperationModal` | Session 对话框状态 | 重命名、新建、移动目标、标签编辑、删除确认；提交/取消 intent |
| `StatusBar` | 选择数、目录项数、操作反馈 | 只读状态与轻量反馈 |

目录被选中时，详情区显示 `InlineSummary + DirectoryDetail`；文本文件被选中时显示
`InlineSummary + TextPreview`；图片和其他文件显示 `InlineSummary + AssetPreview`。元信息不设为
常驻右侧检查器，以免压缩主文件区。

已实现的内存操作集为：新建文件夹、重命名、复制、移动到示例设计目录、删除到回收站、恢复、
收藏、添加“重点”标签、搜索、循环切换排序/筛选、详细列表/缩略图切换和撤销。每个操作由
Controller 转换为可测试的 Model 命令；演示不接入真实文件系统。

## 5. 宿主和后端改造

- CPU/GPU wasm 暴露 `set_viewport(width, height)`；宿主检测 `ResizeObserver` 与
  DPR 变化后设置 CSS canvas 尺寸、物理 backing store 和逻辑 viewport，并使应用壳 dirty。
- raster 后端按逻辑 viewport 与 DPR 输出对应位图；WGPU 用同一 viewport 布局并以物理像素
  配置 surface。输入坐标从 CSS 像素转换到当前逻辑 viewport。
- raster、wgpu、auto 三种查询参数必须构建同一工作区、同一 `UiNode -> UiFrame`，仅最后提交
  后端不同。
- 代码文本来自受控内存数据；图片与归档显示类型化占位，因此不存在图片加载失败路径。WGPU
  诊断仍不得出现 `missing_images`。

## 6. 验收

### 6.1 组件和数据

- `ComponentRuntime` 测试订阅、同轮批处理与订阅释放；组件路径只作为 runtime 内部信息。
- Controller/Model 覆盖单选、目录切换、新建、重命名、复制、删除、恢复、收藏、标签、撤销、
  全局收藏/标签/回收站筛选。

### 6.2 布局和交互

- 在 1440px、1199px、899px 宽度下验证：全视口逻辑 frame、断点结构、窄屏抽屉不压缩详情区；
  宿主 CSS 保证无页面级滚动。
- 目录列表、缩略图卡片行与代码预览均使用定高虚拟列表；不得引入变高虚拟列表或 Grid。
- 浏览器验收确认 CSS canvas 填满视口，DPR 改变后 backing store 更新，指针与滚轮仍映射到
  正确的逻辑坐标。

### 6.3 后端

- CPU frame/交互回归覆盖文件选择、目录切换、modal 提交/取消、窄屏抽屉和 core 命中路由。
- `demo/smoke.cjs` 验证 1366x768 全视口 CPU wasm frame trace 与顶栏/状态栏像素分区；`ops check`、
  `ops build all --gpu`、`ops verify demo` 是交付前的完整 gate。
