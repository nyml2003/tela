# 009-多环境集成

## 1. 四类目标运行环境

| 宿主 | 场景 | 渲染后端 | 输入源 | 特点 |
|---|---|---|---|---|
| 游戏引擎内嵌 | 游戏 HUD、游戏内编辑器、3D 世界贴图 | `tela-render-wgpu` | 引擎输入 + 主机手柄 + 指针 | 嵌入现有渲染循环 |
| 浏览器 | C 端页面、B 端后台 | `tela-render-wgpu`（优先）/ `tela-render-raster`（回退） | 浏览器事件 + IME + 剪贴板 | 同一 `UiFrame`，按 WebGPU 可用性选择 |
| Win32 开发 SDK | 本地桌面调试、系统桥接前置验证 | `tela-render-wgpu` | HWND 消息、鼠标、滚轮、键盘 | 启动时拉取一次 WASM bundle，离线回退最后有效包 |
| 离线 | 单元测试、截图输出 | `tela-render-raster` | 脚本注入 | 确定性、无窗口 |

## 2. 不接管主循环、不独占窗口

tela core 是**被嵌入的库**，不拥有主循环：

- 嵌入方决定何时 tick（刷新）、何时提交绘制、把帧渲染到哪里（叠加层 / 纹理 / 画布）。
- 基座只提供 `build(snapshot) → UiFrame` 的纯核心路径 + `FrameSink` 提交点。
- 输入由嵌入方或平台 SDK 翻译后送入；基座不注册窗口事件循环。

**约定**：任何"驱动"循环（时间推进、动画、输入轮询）都属于宿主，不属于基座。

## 3. 三种宿主各自的适配要点

### 3.1 游戏引擎内嵌

- 渲染到叠加 HUD：把 `UiFrame` 绘制到引擎提供的 HUD 图层。
- 渲染为贴图：把 `UiFrame` 光栅化到纹理，供 3D 世界内 UI 使用（可用 `tela-render-raster` 作为软件贴图生成，或用 wgpu 渲染目标）。
- 输入：引擎把输入事件转成 tela 输入事件注入；主机手柄走主机焦点模型（规约式转移，不依赖布局几何）。
- 资源：纹理/字形由引擎资源系统通过所需的资源通道提供。

### 3.2 浏览器（wasm）

- 核心逻辑编译到 wasm；前端加载器优先以 `tela-render-wgpu` 提交到 WebGPU surface，初始化失败或浏览器无 WebGPU 时回退 `tela-render-raster` 的 RGBA 位图呈现。
- 事件：浏览器 pointer/key/IME/clipboard 事件转成 tela 输入；IME 组合状态只走浏览器文本输入通道。
- 逻辑画布与设备像素比换算由适配层负责，核心只见逻辑坐标。
- 降级：弱特性（如未实现的 Canvas 能力）按 `BackendCapabilities` 降级。

### 3.3 Win32 开发 SDK

- `tela-win32-sdk` 是当前唯一已实现的原生平台壳：它拥有 HWND、Win32 消息循环和 WGPU surface，核心与业务应用均不接触这些对象。
- `ops build bundle` 将同一 `tela-demo` 应用源码编译为无浏览器 import 的 **release WASM guest**，并发布 `dist/tela-dev/latest.json` 与 `tela-demo.tela`。临时包必须先通过 Wasmtime 的首帧与 viewport 校验；壳在**每次进程启动时**请求一次索引和一个 archive。
- 下载包先按索引 SHA-256、ABI、archive 清单和各条目哈希验证，再写入本机最后有效缓存；网络、校验或缓存写入失败不产生半包可见状态。网络失败时只使用仍可验证的旧包。
- 输入在壳边界归一化为指针、滚轮、物理键和基本文本事件；目前实现 Tab/方向键/快捷键、鼠标与 ASCII 文本输入。中文 IME、剪贴板和系统桥接是后续平台能力，不伪装为已支持。
- 浏览器现有运行时不迁移到该 ABI。两条路径共享应用 DSL、`UiFrame` 和 renderer 契约；WASM 包协议只解决原生开发壳的跨进程/跨平台装载。

完整协议、缓存与构建命令见 [023-平台SDK与WASM开发包](023-平台SDK与WASM开发包.md)。

### 3.4 离线渲染

- 软件光栅后端（`tela-render-raster`，实现方案见 [007-绘制与渲染后端](007-绘制与渲染后端.md) 7）确定性输出，适合：
  - 单元测试：同输入同帧断言；
  - 截图输出：`render_frame` 输出位图，可做 snapshot 测试；
  - 文档/预览：无窗口生成界面预览；
  - 服务端批量生成 UI 贴图 / 问题复现基准。
- 输入用脚本注入（合成事件），时钟由测试注入固定值。
- **raster 是像素基准**：统一取整规范以 raster 为准，wgpu/canvas 线上截图与 raster 不一致判为线上渲染 bug。

## 4. 一致性保证

同一套界面描述在各环境下保持布局与交互语义一致：

- 布局与绘制路径共享同一核心，`resolve` 为纯操作 → 布局几何一致。
- 文字度量经同一 `TextMeasurer`（`ab_glyph`，各后端挂载同一字体文件）→ 文本宽度/行高一致。
- 输入语义经同一交互层 → 命中、焦点、模态行为一致；平台只做事件归一化。
- 仅视觉细节按后端能力降级（见 007-3）。

## 5. 一致性验证方式

| 验证 | 手段 |
|---|---|
| 布局一致性 | 离线栅格与线上几何对比（同一树 → 同一 `LayoutBox`） |
| 行为一致性 | 交互层单测（合成事件驱动，断言 `UiAction` 序列） |
| 渲染一致性 | 截图 snapshot 对比 |
| 无窗口可行性 | 核心 + raster 全部验证可在无窗口 CI 环境运行 |

## 6. 规则

- 🔧 主循环与窗口归宿主，基座不接管、不独占。
- 🔧 输入与资源经场景所需的窄平台通道接入，适配层只做事件/格式转换；不建立全功能公共 `Host` trait。
- 🔧 逻辑画布坐标是基座内部唯一坐标；像素比换算只在适配层。
- 🔧 一致性靠同一核心路径保证，禁止在各宿主内复制布局/交互逻辑。
